# 工业纸质工资表闭环与前端交互重构 Implementation Plan

> **适用对象：** Codex、Claude Code、其他具备仓库读写能力的 agentic worker
> **执行方式：** 推荐使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，严格按任务顺序执行并逐项勾选。
> **当前定位：** 本文件是新的开发主线，整合原“工业纸质工资表闭环计划”与后续前端审美、交互、字段逻辑和权限讨论结果。
> **重要边界：** 保留后端状态机、模板版本不可变、审核事务、导出批次和数据库追溯语义；本轮重点补齐真实纸质模板闭环，并重构前端的信息架构与操作逻辑。

---

## 0. 总体目标

将当前“能展示通用技术框、能做基础审核”的系统，升级为可在工厂实际投入验证的纸质工资表闭环：

```text
设计真实纸质模板
→ 发布不可变版本
→ 打印或拼版打印
→ 现场手填
→ 拍照或上传
→ 二维码定位精确模板版本
→ 四角校正与字段裁切
→ OCR / OMR / 数字格识别
→ 左图右表人工核对
→ 规则校验
→ 生成稳定 Excel
→ 导出后更正与重导
→ 全程证据和版本可追溯
```

本阶段必须同时解决两类问题：

1. **工业闭环问题**：真实中文工资表、物理纸张、拼版、二维码、识别、复核、Excel 和实物验收。
2. **前端产品问题**：导航重复、页面冗余、开发者术语、字段逻辑冲突、添加字段 Bug、导出流程混乱、审核工作台没有真正形成“左图右表”。

## 2. 不可偏离的产品规则

### 2.1 本地无登录阶段必须拥有完整权限

当前系统尚未实现登录、身份切换和角色管理，因此正式登录功能完成前，系统必须运行在：

> **本地单机完整权限模式**

默认本地操作员必须能够完成：

- 上传和重新上传表单图片；
- 查找、分类、识别、复核和更正表单；
- 开始审核、暂存、确认、退回、作废；
- 查看历史、证据和审计记录；
- 创建、编辑、预检、发布、克隆、打印和停止使用模板；
- 维护员工、工单、产品和工序；
- 检查导出数据、生成 Excel、下载和重导；
- 完成所有本地开发和实物验收操作。

禁止出现无法解决的权限死路，例如：

- `lacks template.read`
- `lacks template.create_version`
- `403 Forbidden`
- 要求切换用户或联系管理员
- actor、role、permission 等内部术语

内部权限枚举和审计框架可以保留，但本地模式下默认放行全部业务功能。建议通过统一配置控制：

```text
APP_AUTH_MODE=local_full_access
```

未来接入登录后再启用：

```text
APP_AUTH_MODE=authenticated
```

本地模式操作人可统一记录为“本地操作员”，但页面不应显示假的“用户中心”“当前身份”“角色切换”等入口。

### 2.2 现场填写规则

- 工人只填写工号、姓名，以及岗位确实必须填写的少量数字或选择项。
- 工号按纯数字处理，使用逐位数字格，并与员工基础数据自动比对。
- 姓名保留手写线，可以 OCR 辅助，但不得自动放行，必须人工核对原图裁片。
- 班次、岗位、产品、规格、等级等枚举内容优先使用勾选框或预印值。
- 数量、小时数、单价、等级数量等优先使用固定数字格，不使用大块自由文本。
- 自由书写只保留“异常简述 / 事实说明”，且区域要短小。
- 质量、考评、主管、车间主任、填表人、财务等栏目必须按角色分区。

### 2.3 纸张与省纸规则

- 支持 A4、A5、横向、竖向和自定义毫米尺寸。
- 自定义范围：宽 80—420 mm，高 60—594 mm，精度 0.1 mm。
- 编辑器使用毫米网格，默认 1 mm 吸附。
- 坐标仍以归一化值持久化，保证识别兼容。
- 小表默认优先拼版：A4/A3 承载纸、2 拼/4 拼或更多、带裁切线和间距。
- 拼版只影响打印包，不改变每份单表的模板键、版本、坐标和二维码。
- 工号单格不小于 6×8 mm；手写数字格不小于 7×8 mm；勾选框不小于 4×4 mm；手写文本行高不小于 8 mm。
- 外边距不小于 5 mm；二维码成品区不小于 24×24 mm，并保留安静区；四角定位标记不得被业务字段覆盖。

### 2.4 版本与兼容规则

- 已发布模板不可原地修改；修改必须克隆为新草稿版本。
- 现有 4 个通用 V1 模板和历史表单必须继续可读、可打印、可导出。
- 新车间模板使用新的稳定模板键，不覆盖历史 V1，也不绕过种子冲突保护。
- 二维码必须包含精确的 `template_key + version`。
- 拼版中的每份小表都必须拥有自己的二维码。
- 已导入表单永久绑定导入时解析出的模板版本和坐标版本。

### 2.5 候选、预填和正式记录规则

- OCR / OMR 只产生候选和可靠度。
- 候选不得直接覆盖正式记录。
- 自动预填只代表“先填入最终填写值输入框”，不代表自动确认。
- 正式记录必须经过规则校验和人工确认。
- 姓名字段无论 OCR 可靠度多高，都必须人工确认。
- 工号匹配员工库只作为辅助，不得自动替换姓名，也不得因同名自动合并员工。

### 2.6 界面语言规则

页面默认只显示工厂工作人员能理解的中文，不直接展示：

- `template.read`
- `template.create_version`
- actor / payload / schema
- `NEEDS_REVIEW`
- `REEXPORT_REQUIRED`
- 原始 UUID
- 完整哈希
- 技术文件名

错误提示必须回答：发生了什么、为什么不能继续、用户现在可以做什么。原始内部错误只写日志或放进“追溯详情”。

## 4. 审核工作台目标结构

### 4.1 统一双栏核心界面

审核工作台必须围绕“左侧表单图片，右侧识别电子表格”组织：

```text
┌───────────────────────────────────────────────────────────────┐
│ 待核对 / FORM-20260717-001   设备工序单 V1   你正在审核       │
│ [上一张] [下一张]          [更换表单照片] [历史] [证据]       │
├──────────────────────────┬────────────────────────────────────┤
│ 表单图片 / 证据           │ 识别电子表格                       │
│                          │                                    │
│ 原图 / 校正图             │ 字段｜系统识别值｜可靠度           │
│ 字段框叠加                │ 最终填写值｜处理状态               │
│                          │                                    │
│ 缩放｜旋转｜复位          │ 当前字段裁片、候选和规则           │
├──────────────────────────┴────────────────────────────────────┤
│ 规则问题｜历史版本｜证据文件｜审计记录                         │
├───────────────────────────────────────────────────────────────┤
│ [退回重新拍照] [标记无效]      [暂存修改] [确认并审核下一张] │
└───────────────────────────────────────────────────────────────┘
```

桌面建议比例：图片区 46%，电子表格 54%。中间分隔线允许拖动并保存本机偏好。

### 4.2 图片与电子表格双向联动

点击左侧字段框时：

- 右侧自动滚动到对应字段；
- 对应行高亮；
- 最终填写值输入框获得焦点；
- 下方更新字段裁片、候选值和规则。

点击右侧字段行时：

- 左侧自动定位并放大对应区域；
- 当前字段框加粗高亮；
- 其他字段框降低透明度；
- 更新字段裁片、候选和规则。

悬停只做浅色联动，不改变当前选中项。

### 4.3 三类队列共用同一骨架

- **待确认表单类型**：左侧显示图片，右侧显示二维码失败原因、已发布模板版本、模板预览、分类原因和“确认表单类型并开始识别”。识别完成后原地切换为电子表格。
- **待核对**：显示完整左图右表。
- **待重新拍照**：左侧支持旧照片/新照片切换，右侧保留上次电子表格、退回原因和异常字段。新照片识别完成前保留旧结果只读。

### 4.4 空队列规则

空队列时只显示一个完整空状态，不再渲染空图片区、空电子表格、审核锁、底部按钮或重复“当前队列”卡片。

### 4.5 审核锁工作人员化

| 内部概念 | 页面文案 |
|---|---|
| 获取审核锁 | 开始审核 |
| 审核锁有效 | 你正在审核 |
| 锁有效期 | 审核保留至 15:30 |
| 释放审核锁 | 暂停审核 |
| 锁过期 | 审核已暂停，请重新开始 |
| 锁被占用 | 这张表正在由其他工作人员审核 |

## 5. 字段行为模型必须重构

### 5.1 拆分三个独立概念

现有“输入类型、识别引擎、人工填写、自动预填阈值”含义混乱，必须拆成：

#### 纸面填写方式 `PaperEntryMode`

- 手写文字
- 逐位数字格
- 勾选方框
- 签字
- 预印内容
- 无需填写

#### 系统识别方式 `RecognitionMode`

- 不自动识别
- 手写文字识别
- 逐位数字识别
- 印刷文字识别
- 勾选识别
- 二维码识别
- 根据其他字段计算

#### 审核填入方式 `FillPolicy`

- 完全由工作人员填写
- 仅显示识别建议
- 可靠度达到条件时自动填入，仍需最终确认
- 根据规则自动计算

### 5.2 合法组合

| 系统识别方式 | 允许的填入方式 | 是否显示可靠度阈值 |
|---|---|---:|
| 不自动识别 | 完全由工作人员填写 | 否 |
| 手写文字识别 | 仅显示建议 / 达到条件自动填入 | 是 |
| 逐位数字识别 | 仅显示建议 / 达到条件自动填入 | 是 |
| 印刷文字识别 | 仅显示建议 / 达到条件自动填入 | 是 |
| 勾选识别 | 仅显示建议 / 达到条件自动填入 | 是 |
| 二维码识别 | 仅显示建议 / 达到条件自动填入 | 可配置 |
| 自动计算 | 根据规则自动计算 | 否 |

选择“不自动识别”后，必须立即隐藏自动填写条件、清除旧阈值、清除候选策略，并强制 `FillPolicy = MANUAL_ONLY`。不能只隐藏控件而继续向后端提交旧值。

### 5.3 姓名和工号固定规则

- **工号**：逐位数字格、逐位数字识别、纯数字、自动与员工库比对；空值、非数字、长度异常或员工库无记录时必须人工处理。
- **姓名**：手写文字线，可用 OCR 作为建议，但无论可靠度多高都必须展示原图裁片并由人工确认，不得因工号命中自动替换姓名。

## 6. 模板中心重构

### 6.1 模板库

页面名称建议为“模板管理”，说明为“创建、编辑和发布车间使用的纸质表单模板”。

模板库一级页面删除：

- 返回审核工作台；
- 重复的模板中心面包屑；
