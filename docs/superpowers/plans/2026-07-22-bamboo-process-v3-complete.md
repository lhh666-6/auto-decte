# 竹丝工序记录 V3 完整实现说明

## 交付范围

本次实现覆盖移动端竹丝工序从生产签字到财务入账的完整闭环，并保留原网页端功能。正式业务动作必须联网；PWA 离线状态只允许保存草稿。

流程顺序：

1. 分选人填表并签字，同时生成分选工资事实，状态为待生效。
2. 浸胶人、干燥人分别填表和签字；两者都完成后生成一条联合工资事实，并分别记录两人的工资分配。
3. 前三个生产环节完成后，检测人可以自行填写检测序号，选择被检测环节，多次登记含水率，并用照片、录音或文字留痕。
4. 未关闭的检测异常会阻止主管签字；主管签字后关闭本版本的检测窗口。
5. 厂长在主管签字后等待配置时长（默认 12 小时）再审核。厂长通过后，工资事实生效并进入当日财务批次。
6. 财务逐条批准、暂缓或要求纠错。只有已批准条目进入月汇总；财务可查看原始表单并向厂长询问。
7. 纠错由主管选择确实需要重写的工序。系统自动作废该工序及下游签字/工资事实，但保留旧版本审计记录；重新完成后生成补充批次。

## 身份与工厂边界

- `SYSTEM_ADMIN`：新建工厂，分配厂长和财务等高权限职务，可发布系统默认工资规则。
- `PLANT_MANAGER`：在本厂分配主管、检测人和生产工人，审批工人的换岗申请，发布本厂工资规则覆盖版本，审核生产表单，回复财务询问。
- `SUPERVISOR`：审核整张电子表单，关闭异常后签字，选择需要回退重写的工序。
- `INSPECTOR`：在前三个生产工序完成后执行检测和证据留痕。
- 三类生产工人：分选、浸胶、干燥；可申请在生产职务之间切换，厂长批准后生效。
- `FINANCE_APPROVER`：按日逐条处理工资，回溯原始表单，发起询问，导出单日明细或月汇总。

员工任一时刻只有一个生效工厂和一个竹丝职务。历史分配不会删除。没有职务的新员工保持待分配状态。角色定义和工厂均为数据表记录，可继续新增工人职务和工厂。

## 关键数据与审计约束

- 迁移版本：`016`。
- 工资规则按系统默认/工厂覆盖分层并版本化；每条工资事实保存规则版本、输入快照、分配和来源签字。
- 所有生产签字和检测签字保存人员、工厂、职务、服务端时间、设备、请求号、幂等键和 SHA-256 摘要。
- 选择性回退只把当前版本标记为失效，不物理删除提交、签字、检测、工资或财务记录。
- 财务允许同一日批次部分批准、部分暂缓；纠错重做后生成带来源批次的补充版本。

## 移动 API

基础前缀：`/api/v1/mobile/bamboo`

- 工序：`/records`、`/tasks`、`/records/{id}/stages/{stage}/submit`
- 工资和检测汇总：`/records/{id}/operations`
- 检测：`/records/{id}/inspections`、`/inspections/{id}/evidence`、`/inspection-exceptions/{id}/close`
- 回退：`/records/{id}/return`
- 换岗：`/role-change-requests` 及其审批接口
- 工资规则：`/payroll-rules`
- 人员和工厂：`/admin/assignments`、`/admin/factories`
- 财务：`/finance/daily-batches`、逐条审批、询问/回复、`/finance/monthly-summary`、`/finance/export.xlsx`

所有写接口要求当前移动会话、CSRF 头和 `Idempotency-Key`。跨厂记录统一按不可见处理。

## 运行配置

环境变量 `FORM_DEMO_BAMBOO_PLANT_AUDIT_WAIT_HOURS` 控制厂长审核等待时长，默认 `12`。测试环境可以设为 `0`。

## 自动化验收

`tests/api/test_mobile_bamboo_operations_ds.py` 覆盖：工资锁定与联合工资、检测异常门禁、厂长审核生效、财务逐条审批、月汇总和 XLSX、财务询问、主管选择性回退、补充批次、换岗审批、新员工职务分配、工厂规则版本和新增工厂。
