# 移动端流程可用性整改设计

## 目标

在不改变“分选表”和“浸胶+干燥表”独立审核生命周期的前提下，修复移动端岗位管理、上游查找、检测、回退、厂长审核和数据防丢问题，使工人按实际业务语言完成操作。

## 1. 职务与人员管理

- 工人申请换岗时只能选择管理员已发布、启用且允许申请的预设工种；界面使用中文名称和原生下拉选择，并保留明确的“提交申请”按钮。
- 厂长首页把“换岗审批”和“本厂人员”拆成两个入口、两个独立底部面板。
- 换岗审批显示人员姓名、当前职位、目标职位、申请原因和同意/驳回操作。
- 厂长不能创建新职位，也不能通过输入未知职位代码绕过限制；只有管理员维护职位定义。
- 厂长可以为本厂新增人员。新增时填写姓名、初始 PIN，并从可分配预设职位中选择；系统自动生成工号，业务界面始终以“姓名（工号）”展示。
- 厂长可以从本厂人员列表中选择员工后调整到预设职位；不能分配厂长、财务或系统管理员职位。

## 2. 按笼号处理上游记录

- 笼号是跨环节查找键，但不合并表单生命周期。
- 浸胶工先输入或选择笼号，系统只返回当前工厂、当前处于浸胶步骤的“浸胶+干燥表”，并展示其来源分选快照。
- 干燥工先输入或选择笼号，系统只返回当前工厂、已经完成浸胶且当前处于干燥步骤的联合表，并展示浸胶数据。
- 检测人也按笼号检索，不需要逐张打开记录。
- 后端查询必须同时校验工厂、角色、当前步骤和笼号，前端过滤不能替代权限校验。

## 3. 检测窗口

- 分选表在分选签字完成后开放检测；联合表在浸胶和干燥生产签字都完成后开放检测。
- 检测窗口与主管待审核阶段并行，在主管签字前关闭。
- 检测异常未关闭时仍阻止主管签字；正常检测不是主管签字的强制前置条件。
- 检测继续支持检测序号、目标生产步骤、文字、照片和录音留痕。

## 4. 正常通过、回退和厂长审核

- 主管默认动作是“审核通过并签字”。只有点击“发现问题，发起回退”后才展开工序选择和回退原因。
- 选择“不回退/通过”绝不进入回退表单。
- 主管签字后厂长立即可审核，不再设置隐藏的 12 小时等待期。
- 后端错误统一使用中文业务提示，不向用户显示英文内部异常。

## 5. 自动缓存与历史记录

- 新建分选、浸胶、干燥、主管审核、厂长审核和检测文字字段均自动保存到本机。
- 缓存键包含账号、工厂、设备、记录和步骤；不同人员或工厂不会互相恢复数据。
- 成功提交后清除对应缓存；刷新、误关闭和网络中断后恢复。文件附件因浏览器限制不持久化，恢复时提示重新选择。
- “提交记录”改为显示竹丝流程的本人处理历史，包含表单类型、笼号、本人处理步骤、时间和当前流转状态；不再只查询旧电子提交表。

## 6. PWA 桌面入口

- “我的”页面提供“添加到桌面/安装应用”。支持 `beforeinstallprompt` 的浏览器可一键安装。
- 已安装时显示“已安装”；微信或不支持安装事件的浏览器显示简短的“在浏览器中打开并添加到主屏幕”指引。

## 7. 验收标准

- 所有职位选择均来自后端预设，厂长无法创建职位。
- 浸胶、干燥和检测人不输入笼号时不展示整批待办；按笼号可准确找到当前可处理记录。
- 主管通过不出现回退选择，厂长可立即签字。
- 刷新后未提交输入恢复，成功后缓存清除。
- 本人历史能看到竹丝工序签字记录，PWA 安装入口状态正确。
