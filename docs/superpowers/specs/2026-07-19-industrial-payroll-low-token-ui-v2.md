# 工业纸质工资表系统：低 Token 实施与统一 UI 规范

> 本文是后续交给 Codex 执行的主文档。目标是在尽量少用 Token、减少返工和减少开发人员自由发挥的前提下，完成核心审核闭环、真实纸质模板、批量图片管理、多类型报表和只读型 AI 辅助。

## 1. 已确认的产品决定

### 1.1 本地无登录完整权限

正式加入登录前，系统运行在“本地单机完整权限模式”。

默认操作员必须可以：

- 上传、批量导入、查找、分类、识别和复核表单；
- 暂存、确认、更正、退回和标记无效；
- 创建、编辑、检查、发布、打印和停止使用模板；
- 维护员工、工单、产品和工序；
- 生成、下载和重导 Excel；
- 查看历史、证据和审计记录。

前端不得显示 `403`、权限代码、角色代码或要求用户切换账号。内部权限框架可以保留，但本地模式必须默认放行。

### 1.2 全局导航固定为四个模块

```text
工业工资表系统 | 审核工作台 | 模板中心 | 基础数据 | 导出数据
```

- “工业工资表系统”只是品牌，不可点击。
- 未实现登录前不显示用户、身份和角色入口。
- 审核工作台内部只保留：
  - 待确认表单类型
  - 待核对
  - 待重新拍照
- 删除左侧重复入口：数据管理、模板与字段、员工/工单、产品/工序、可导出。

### 1.3 审核工作台固定采用左图右表

```text
┌───────────────────────────────────────────────────────────────┐
│ 待核对 / 表单编号 / 模板版本 / 你正在审核                     │
│ [上一张] [下一张] [更换照片] [历史] [证据]                    │
├──────────────────────────┬────────────────────────────────────┤
│ 表单图片                  │ 识别电子表格                       │
│ 原图 / 校正图             │ 字段｜系统识别值｜可靠度           │
│ 字段框叠加                │ 最终填写值｜处理状态               │
│ 缩放｜旋转｜复位          │ 当前字段裁片、候选和规则           │
├──────────────────────────┴────────────────────────────────────┤
│ 规则问题｜历史版本｜证据文件｜审计记录                         │
├───────────────────────────────────────────────────────────────┤
│ [退回重新拍照] [标记无效] [暂存修改] [确认并审核下一张]      │
└───────────────────────────────────────────────────────────────┘
```

必须实现图片字段框和电子表格行双向联动。空队列只显示一个空状态，不再渲染空图片区和空表格。

### 1.4 模板压缩为 5—6 个核心版面

推荐保留：

1. 计时类工资表
2. 叉车/设备计时工资表
3. 装架与干燥计件工资表
4. 炉类作业工资表
5. 热压生产明细工资表
6. 开片生产明细工资表

模板负责版面结构，岗位配置负责标题、固定选项、单价、扣减和导出映射。二维码必须同时定位模板版本和岗位配置版本。

### 1.5 DeepSeek AI 只读

AI 允许：

- 回答问题；
- 解释排除原因；
- 推荐报表、筛选、分组和汇总；
- 分析 Excel 样表结构；
- 生成临时报表草案；
- 指导下一步操作。

AI 禁止：

- 修改正式记录、模板和基础数据；
- 直接发布报表；
- 直接生成、重导或删除文件；
- 执行模型生成的 Python、SQL、Shell、JavaScript 或任意公式。

AI 只能填充临时草稿，最终操作必须由用户确认。

## 2. P0 必修问题

### 2.1 修复导航重复

| 当前入口 | 新处理 |
|---|---|
| 数据管理 | 改为“上传表单照片”按钮 |
| 模板与字段 | 统一进入模板中心 |
| 员工/工单 | 统一进入基础数据 |
| 产品/工序 | 统一进入基础数据 |
| 可导出 | 统一进入导出数据 |
| 一级页面返回审核工作台 | 删除 |
| 可点击产品名 | 改为不可交互品牌 |

### 2.2 修复字段行为模型

拆分三项：

**纸面填写方式**

- 手写文字
- 逐位数字格
- 勾选方框
- 签字
- 预印内容
- 无需填写

**系统识别方式**

- 不自动识别
- 手写文字识别
- 逐位数字识别
- 印刷文字识别
- 勾选识别
- 二维码识别
- 自动计算

**审核填入方式**

- 完全由工作人员填写
- 仅显示识别建议
- 达到可靠度时自动填入，仍需人工确认
- 自动计算

当选择“不自动识别”时，必须隐藏并清除自动填写阈值，后端也不得保存旧值。

### 2.3 修复新增字段 Bug

- 新增字段与当前字段编辑状态完全隔离；
- 新增时使用空白状态；
- 取消新增不修改当前字段；
- 字段编号唯一；
- 双击防重复；
- 添加失败回滚；
- 添加成功自动选中新字段；
- 类型变化后清理不适用配置；
- 新增、复制、删除、移动和缩放至少支持一步撤销。

### 2.4 正式打印层与识别层分离

正式 PDF/PNG 只包含：

- 中文标题
- 黑色表格线
- 数字格
- 勾选框
- 签字线
- 二维码
- 四角定位标记
- 裁切线

蓝色识别框只能出现在网页调试预览中。预览提供“业务版面 / 显示识别区域”切换。

# 4. 纸质表格模板详细样式

> 本节用于提前固定纸质表格的版面、字段类型和填写限制，减少工人自由书写，降低识别难度。  
> 后续模板设计器、打印预览、识别区域和 Excel 映射均以本节为基线，不允许开发人员自行改变表格结构。

## 4.1 减少自由填写的统一原则

### 4.1.1 字段类型优先级

所有纸质字段按以下优先级设计：

1. **预印固定内容**
2. **二维码自动带入**
3. **数字格**
4. **单选勾选框**
5. **多选勾选框**
6. **固定编号选项**
7. **短数字栏**
8. **短文本栏**
9. **自由说明栏**

自由说明栏必须是最后选择，只用于无法结构化的异常事实。

### 4.1.2 工人可填写内容限制

工人原则上只填写：

- 工号数字格；
- 日期数字格；
- 数量数字格；
- 时间数字格；
- 单选或多选勾选框；
- 必要签字；
- 极少量异常说明。

工人不应自由填写：

- 模板名称；
- 工序名称；
- 产品名称；
- 班组名称；
- 单位；
- 单价；
- 计算结果；
- 奖励规则；
- 扣减规则；
- 工资合计；
- Excel 列名；
- 工单正式名称；
- 设备正式名称。

这些内容应由模板、岗位配置、二维码、基础数据或系统计算确定。

### 4.1.3 通用字段控件

| 字段类型 | 纸面样式 | 示例 | 识别方式 |
|---|---|---|---|
| 日期 | 逐位数字格 | `2 0 2 6 年 0 7 月 2 1 日` | 逐位数字识别 |
| 工号 | 6—8 位数字格 | `□ □ □ □ □ □` | 逐位数字识别 + 基础数据校验 |
| 班次 | 单选框 | `□白班 □夜班` | 勾选识别 |
| 岗位 | 预印或单选 | `岗位：叉车工` | 不识别或勾选识别 |
| 工单 | 二维码或数字格 | `□ □ □ □ □ □ □ □` | 二维码 / 数字识别 |
| 数量 | 数字格 | `□□□` | 逐位数字识别 |
| 小数 | 分隔数字格 | `□□□.□□` | 逐位数字识别 |
| 时间 | 结构化数字格 | `□□:□□` | 逐位数字识别 |
| 是否项 | 单选框 | `□是 □否` | 勾选识别 |
| 结果等级 | 单选框 | `□合格 □需改进 □不合格` | 勾选识别 |
| 签字 | 固定签字线 | `员工签字：________` | 人工确认 |
| 异常说明 | 2—3 行短栏 | 每行限制 20—25 字 | 手写识别 + 人工确认 |

### 4.1.4 禁止使用的纸面设计

禁止：

- 一个大空白框要求工人自由描述整天工作；
- 让工人自己写工序名称；
- 让工人自己写单位；
- 让工人手算工资总额；
- 让工人自己写“白班”“夜班”；
- 在一格中同时填写多个数字；
- 使用没有边框的长横线填写复杂编号；
- 同一项同时提供文本输入和勾选；
- 在正式打印版中出现字段代码、坐标和技术键。

## 4.2 通用页头与页脚

所有核心模板统一使用以下页头。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│                         XX车间日工资表                                   │
│ 模板编号：系统预印      岗位：系统预印      表单二维码：右上角固定       │
├──────────────┬────────────────────┬──────────────┬──────────────────────┤
│ 日期         │ □□□□年□□月□□日   │ 班次         │ □白班  □夜班         │
├──────────────┼────────────────────┼──────────────┼──────────────────────┤
│ 工号         │ □ □ □ □ □ □      │ 姓名         │ 系统匹配/人工核对     │
├──────────────┼────────────────────┼──────────────┼──────────────────────┤
│ 班组         │ 预印或勾选         │ 工单号       │ 二维码/数字格         │
└──────────────┴────────────────────┴──────────────┴──────────────────────┘
```

统一规则：

- 模板标题、岗位名称、班组和单位优先预印；
- 工号由工人填数字格；
- 姓名不要求工人重复自由填写，系统根据工号匹配；
- 只有工号匹配失败时，审核人员在电子表格中确认姓名；
- 日期使用数字格；
- 班次只能单选；
- 工单优先使用二维码或预印短码；
- 工人不得填写模板编号和版本。

统一页脚：

```text
┌────────────────────┬────────────────────┬────────────────────┬──────────┐
│ 员工签字           │ 班组长确认         │ 车间主管确认       │ 页码     │
│ ____________       │ ____________       │ ____________       │ 1 / 1    │
└────────────────────┴────────────────────┴────────────────────┴──────────┘
```

签字规则：

- 工人只签自己；
- 班组长和主管分别签字；
- 不允许一个人代签多个角色；
- 签字图只用于证据，不自动识别姓名；
- 需要电子确认的角色由系统另行记录。

## 4.11 纸质模板发布前检查

每个模板发布前必须自动检查：

- 是否存在标题；
- 是否存在模板二维码；
- 是否存在表单实例二维码区域；
- 是否存在四角定位标记；
- 数字格位数是否明确；
- 所有勾选组是否设置单选或多选；
- 多选组是否有最大选择数；
- 异常说明是否设置条件必填；
- 所有金额是否由系统计算；
- 是否存在不必要的大面积自由填写区；
- 是否存在无法识别的超小字段；
- 字段是否超出安全边距；
- 蓝色调试框是否从正式打印层移除；
- A4/A5 纸张方向是否使用中文；
- Excel 映射是否完整；
- 岗位配置是否明确；
- 二维码是否能解析到精确模板版本和岗位配置版本。

发布失败时必须逐项显示中文原因。

# 5. 批量导入、图片总览与存储

### 4.1 多图上传

导入入口：

```text
将多张照片拖到这里
[选择多张照片] [选择文件夹] [从手机上传]
```

必须支持：

- 多选、拖拽和文件夹；
- 每张图片独立状态；
- 单张失败不影响整批；
- 单张重试；
- 重复图片提示；
- 2—4 张并发；
- 后台继续处理。

### 4.2 导入批次与图片总览

批次显示：

```text
本次导入 36 张
成功 28｜处理中 4｜需要处理 3｜失败 1
```

提供“缩略图视图 / 详细列表”。

审核工作台增加：

```text
[任务视图] [图片总览] [导入批次]
```

点击缩略图直接进入左图右表审核页。

### 4.3 不依赖公网服务器

分阶段实现：

1. 浏览器多选、拖拽和文件夹导入；
2. 本地目录监听；
3. 同一局域网手机扫码上传。

### 4.4 图片存储

正式关系使用关系数据库：

```text
图片资产 → 证据版本 → 表单 → 记录版本 → 导出批次项
```

图片不存数据库。数据库只存 ID、哈希、路径、大小、宽高、格式、表单编号、证据版本和批次信息。

目录建议：

```text
data/
├─ originals/
├─ rectified/
├─ thumbnails/
├─ exports/
├─ cache/
└─ archive/
```

四层存储：

- 原图永久保留；
- 校正图用于识别；
- 缩略图用于图片墙；
- 字段裁片按需生成，关键异常才永久保存。

SHA-256 用于完全去重，pHash/dHash 仅用于相似提示。支持 SSD 热数据、普通硬盘/NAS 温数据和归档盘冷数据。

# 8. 低 Token 执行规则

## 7.1 一次只做一个任务

每个任务控制在：

- 1 个明确目标；
- 1—3 个模块；
- 3—8 个主要文件；
- 一组相关测试；
- 1 次提交。

禁止一次要求重构全部前端、模板、存储、报表和 AI。

## 7.2 固定读取范围

每次只读取：

```text
AGENTS.md
docs/CURRENT_STATUS.md
docs/NEXT_TASK.md
docs/DECISIONS.md
当前任务
当前任务明确列出的代码和测试
```

禁止默认扫描整个仓库、所有 Markdown、历史 handoff、node_modules 和构建产物。

## 7.3 标准任务提示词

```text
目标：
[一个明确目标]

只读取：
- AGENTS.md
- CURRENT_STATUS.md
- NEXT_TASK.md
- DECISIONS.md
- [明确文件]

只修改：
- [明确模块]

不要修改：
- [明确排除项]

验收：
- [行为]
- [测试命令]

完成后只汇报：
1. 修改文件
2. 行为变化
3. 测试结果
4. 剩余风险
5. 提交哈希
```

## 7.4 测试策略

小任务只运行局部测试。里程碑结束、合并前和实物验收前才运行全量：

```bash
python -m pytest -q
python -m ruff check app tests
python -m mypy app config
npm --prefix frontend test -- --run
npm --prefix frontend run build:web
```

## 7.5 文档维护

固定维护：

- `docs/CURRENT_STATUS.md`：真实完成内容和测试结果；
- `docs/NEXT_TASK.md`：只写下一个任务；
- `docs/DECISIONS.md`：不可重新讨论的决定；
- `docs/FRONTEND_ACCEPTANCE.md`：本文 UI、图标、表格和页面验收规范。

# 10. 完成判定

全部满足后才算完成：

- 无登录状态下所有核心功能可用；
- 顶部和侧栏无重复入口；
- 审核工作台实现左图右表和双向联动；
- 人工录入不显示也不保存自动填写阈值；
- 新增字段不会复用或覆盖当前字段；
- 正式打印文件不包含蓝色调试框；
- 工号使用数字格；
- 班次和考评使用勾选组；
- 姓名和签字使用手写线；
- 模板压缩为 5—6 个核心版面；
- 支持批量上传、导入批次和图片总览；
- 图片采用分层存储、缩略图和去重；
- 支持快速导出和多种报表；
- AI 只能回答和生成草稿；
- 所有页面遵循统一颜色、图标、按钮、表格和状态规范；
- 页面不直接显示英文状态码、权限码和技术 ID；
- 局部测试和阶段全量测试全部通过。

---

# 11. 明确不算完成

以下情况不算完成：

- 只修改颜色、圆角和间距；
- 不同开发人员继续自行选择图标和颜色；
- 顶部和侧栏继续重复；
- 模板仍然是字段名称加蓝框；
- PDF 仍含调试框；
- 人工录入仍显示自动填写阈值；
- 新增字段仍可能覆盖当前字段；
- 一次只能上传一张图片；
- 一张失败导致整批失败；
- 图片全部堆在系统盘；
- 导出只能生成原始电子表格格式；
- AI 可以直接修改、发布或执行；
- 页面继续显示 `landscape`、`DRAFT`、UUID 和权限代码；
- 同一功能使用多个不同图标；
- 状态标签发生换行；
- 绿色继续用于新增、保存和预览按钮。
