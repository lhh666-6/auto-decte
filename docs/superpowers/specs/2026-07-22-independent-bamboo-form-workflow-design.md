# 竹丝独立表单与跨表数据依赖设计

## 1. 目标与适用范围

本设计替代“把分选、浸胶、干燥、主管和厂长串成一张大表”的旧理解。

系统必须同时支持两种关系：

1. **表单生命周期**：每张工资表单独立完成填写、签字、主管审核、厂长审核、生效和财务结算。
2. **跨表数据依赖**：后一张表可等待并复用前一张表产生的数据，但两张表的状态、版本、退回、签字和工资事实互不合并。

本期落地两类竹丝表单：

- `SORTING`：分选或分选+装笼表。
- `DIPPING_DRYING`：浸胶+干燥联合表。

该模型必须可扩展到后续新增工种、工厂和表单类型，不得在状态机中写死“所有表单必定是一条固定生产链”。

## 2. 核心领域模型

### 2.1 生产对象

生产对象表示同一批或同一笼竹丝，是跨表数据关联的载体。它具有稳定标识，保存笼号、生产日期和工厂等公共信息，但不承载审批状态。

### 2.2 独立表单

每张表单至少包含：

- 表单标识、表单编号、表单类型。
- 所属工厂、生产对象标识。
- 当前步骤、表单状态和修订号。
- 当前有效数据快照。
- 字段来源引用，用于追踪复用数据来自哪张表单的哪个版本。
- 各步骤提交、电子签名、退回和失效历史。

统一生命周期为：

```text
DRAFT/OPEN
→ PRODUCTION_SIGNED
→ SUPERVISOR_REVIEW
→ PLANT_AUDIT
→ EFFECTIVE
→ FINANCE_PENDING / FINANCE_APPROVED / CORRECTION_REQUIRED
```

其中生产步骤允许按表单类型配置：

- `SORTING` 只有一个生产签字步骤：分选人提交并签字。
- `DIPPING_DRYING` 有浸胶录入和干燥联合确认两个生产步骤；干燥确认后形成该表的生产签字完成状态。

### 2.3 跨表依赖

依赖关系单独保存，不由表单审批状态隐式推导。至少记录：

- 上游表单标识和版本。
- 下游表单标识。
- 依赖用途，例如“开放生产”“复制基础字段”“工资计算来源”。
- 字段映射和数据快照。
- 上游变更后的影响状态。

下游表单复制的是带来源信息的数据快照，不直接读取可能变化的上游当前值。这样可以还原当时使用的数据，并在上游被退回或改版时准确提示影响。

## 3. 业务流程

### 3.1 分选或分选+装笼表

1. 分选人新建表单并选择作业模式：`分选`或`分选+装笼`。
2. 填写 V3 原型规定的分选字段，核对后签字提交。
3. 提交后，这张表的生产步骤立即显示“已完成”，进入主管审核；不能继续显示为“等待浸胶”。
4. 同时，分选数据向允许的下游表单开放，供浸胶+干燥表复用。
5. 主管查看整张分选表，可通过并签字或退回分选步骤。
6. 厂长在主管通过后查看整张分选表，可通过并签字或退回。
7. 厂长通过后表单生效，生成独立的分选或分选+装笼工资事实。
8. 财务网页端仅汇总已生效表单，并对工资条目审批、暂缓或要求更正。

### 3.2 浸胶+干燥联合表

1. 下游人员从已提交的分选表中选择生产对象；系统复用笼号、长度、品级、深浅、把数、净重等允许复用的字段，并显示来源表单编号。
2. 浸胶人填写浸胶数据。浸胶提交保存为本联合表的第一段生产记录，不结束整张联合表。
3. 干燥装架人只有在浸胶记录完成后才能填写干燥数据。
4. 干燥人核对浸胶与干燥数据并完成联合确认签字。此时该联合表的生产步骤完成，进入主管审核。
5. 主管和厂长分别对这张联合表审核签字。
6. 厂长通过后，该联合表独立生效并生成浸胶+干燥工资事实。

### 3.3 并行关系

分选表提交后产生两个并行结果：

```text
分选提交
├─ 分选表 → 主管审核 → 厂长审核 → 生效 → 财务结算
└─ 释放可复用数据 → 浸胶+干燥表 → 主管审核 → 厂长审核 → 生效 → 财务结算
```

下游生产不要求等待分选表完成主管和厂长审核；它只要求分选生产数据已经签字提交。若上游后来被退回并修改，系统对关联下游表标记“上游数据已变更，待确认”，由主管决定需要重写哪些部分。

## 4. 字段与计算

### 4.1 分选表

- 自动带出：操作人、班组、服务器时间、工厂。
- 作业模式：`分选`、`分选+装笼`。
- 特殊类：直装、防霉，可多选。
- 长度：2.1、2.3、2.5。
- 深浅：深、浅。
- 品级：A、B。
- 供应商：选填。
- 笼号：必填。
- 把数：正整数。
- 净重：按已发布规则自动计算。
- 含水率：至少一个检测点，值为 1 至 100 的正整数。

长度、深浅、品级、特殊类以及净重规则来自管理员发布的配置。移动端只允许选择已发布选项，不能临时新增或修改。

### 4.2 浸胶+干燥联合表

- 复用并展示分选表公共字段和来源。
- 浸胶段：胶前重、胶后重、上胶量、含水率以及已配置的浸胶业务字段。
- 干燥段：含水率、一个或多个不重复的干燥架号以及已配置的干燥业务字段。
- 联合工资事实只在干燥联合确认、主管审核和厂长审核均完成后生效。

## 5. 审核、退回和版本

- 每次提交产生不可覆盖的新版本和电子签名；历史版本不删除。
- 主管和厂长可查看整张当前表、历史版本、签字人、服务器时间和关联表单。
- 退回原因必填，并指定需要重写的生产步骤或字段范围。
- 退回仅重开指定部分；受影响的后续提交标记失效，不要求无关人员重复填写。
- 上游表单修改时，系统根据字段映射计算关联表单影响，并显示来源版本差异；是否重写由有权限的主管决定。
- 厂长审核签字后表单才具有工资结算效力。

## 6. 检测支线

- 检测人可在前三类生产记录中选择检测目标和自定义检测序号。
- 检测记录支持照片、录音和文字证据。
- 检测人、主管和厂长可查看其权限范围内的完整电子表单及关联来源。
- 检测记录独立留痕，不自动替代主管或厂长的退回决定。
- 检测异常需要返工时，通过正式退回流程指定受影响表单和步骤。

## 7. 权限边界

- 管理员：确定财务和厂长，维护全局角色及可发布配置。
- 厂长：管理本厂主管、工人、检测人及换岗申请，并负责本厂表单审核。
- 主管：审核生产表单，决定退回范围并填写评价。
- 工人：只能填写与当前有效职务匹配的生产步骤。
- 检测人：执行检测并查看已开放的生产对象和完整关联记录。
- 财务：仅使用网页端审批已生效工资条目、导出单日或月度汇总、回溯原始表单并向厂长询问。

身份由正式权限系统提供。V3 原型中的演示身份下拉框不进入正式移动端。

## 8. 移动端界面与交互

正式移动端复用 V3 原型的视觉和交互规范：

- 最大内容宽度 520px、移动端单列卡片、绿色视觉体系、安全区适配。
- 底部四栏导航：`首页 / 记录工作 / 提交记录 / 我的`。
- 工作列表按当前职务显示`可记录 / 等待上游 / 已完成`。
- “已完成”表示当前用户负责的生产步骤已经提交，不表示关联生产对象的全部表单均已结束。
- 表单字段、底部选择 Sheet、含水率增删、自动平均值、核对确认 Sheet 和签字按钮按 V3 原型交互实现。
- 每张独立表单显示自己的状态条，例如`生产填写 → 主管审核 → 厂长审核 → 已生效`。
- 关联表单和复用字段显示来源表单编号、版本及变更提醒，但不混入本表状态条。
- 主管、检测人和厂长详情页展示整张电子表单、签字、退回、版本和关联来源。
- PWA 保持可安装和离线外壳能力；正式签字、审核和媒体上传必须联网。

## 9. 财务网页端

- 财务端不复用移动端生产工作台。
- 工资列表以“已生效的独立表单”为最小汇总单位。
- 分选表和浸胶+干燥表分别生成工资事实，不因共享生产对象而合并审批状态。
- 支持单日导出、月度汇总、XLSX 生成、审批结果、原始表单回溯和向厂长询问。
- 任何待更正或未生效表单不得进入已批准工资汇总。

## 10. 可扩展配置边界

新增表单类型时通过配置定义：

- 表单类型和生产步骤。
- 每个步骤允许的职务。
- 字段、预设选项、校验和计算规则。
- 主管与厂长审核链。
- 上游依赖、字段映射和开放条件。
- 工资事实生成规则。

状态机处理统一表单生命周期；依赖服务处理跨表开放、数据快照和变更影响。两者必须保持独立接口。

## 11. 验收标准

1. 分选人提交后，分选表立即出现在本人“已完成”，当前状态为待主管审核。
2. 分选提交后可创建关联浸胶+干燥表，同时分选表审核继续推进。
3. 浸胶+干燥表能够显示并追踪复用字段来源。
4. 两张表分别完成主管和厂长审核，并分别生成工资事实。
5. 任一表单被退回时，不会删除历史签字，也不会无条件重开所有关联表单。
6. 财务只能汇总已生效表单，且可从工资条目回溯到原始表单版本。
7. 移动端关键页面和交互与 V3 HTML 一致，身份演示切换除外。
8. 新增第三种依赖表单时不需要修改统一状态机的固定阶段枚举。
