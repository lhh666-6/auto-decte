# Web 三角色工作区剩余开发与最终验收设计

日期：2026-07-23
状态：已确认，作为后续增量开发基线
目标分支：`modular-architecture`

## 1. 文档目的

本文以当前代码为起点，定义管理员、财务、厂长三个 Web 工作区尚未完成的开发内容、后台闭环、实施顺序和最终验收标准。

本文不是重写方案。已经稳定的统一登录、Bamboo 生产流程、移动端工人业务、表单版本、审批、工资、报表和审计基础设施继续复用；后续开发只补齐缺失能力、修复错误数据链路和完善用户界面。

本文同时修正此前“阶段已经全部通过”的过早结论。在本文验收标准全部通过前，当前版本只能用于开发测试，不得标记为最终生产可用版本。

## 2. 需求依据与优先级

后续开发按以下优先级解释业务规则：

1. 用户在当前项目会话中最后确认的业务规则；
2. 本文；
3. `2026-07-23-production-governance-inspection-security-design.md`；
4. `2026-07-23-plant-web-bamboo-unification-design.md`；
5. `Web三角色端与后台服务转型开发设计.md`；
6. 更早的管理员、财务和纸质识别设计。

出现冲突时必须采用较高优先级规则，不得同时实现两套状态或两套流程。

特别明确以下覆盖关系：

- 表单、流程和工资规则的最终审批、按厂启用、停用、恢复和退役权属于管理员。
- 厂长不审批或启用系统配置，但可以在 Web 端执行本厂生产签字、选择环节打回、检测提前终止、检测上诉审批和人员调动职责。
- 厂长只保留 Web 业务端；工人、主管和检测员继续使用移动端。
- 厂长知悉通知不阻塞管理员已经作出的启用决定。

## 3. 当前基线

### 3.1 已有能力

- 管理员、财务、厂长使用统一 Web 登录入口，根据账户角色跳转到对应工作区。
- 移动端继续使用统一员工账户体系。
- 财务表单版本、管理员审批、按厂启用和厂长通知已有后台骨架。
- 财务业务梳理、工作流版本、工资规则、工资批次、报表模板、映射和导出已有基础服务。
- 厂长 Web 已有本厂概览、通知、表单、流程、生产、签字、打回、异常、员工调动和工资入口。
- 厂长 Web 与主管移动端打回已使用相同 Bamboo 事实源，并具备幂等键和乐观版本保护。
- Web 前端生产构建能够通过。

### 3.2 当前阻塞问题

以项目 `.venv` 执行阶段核心后端测试时，当前结果为 23 项通过、2 项失败：

1. 厂长查询本厂生产记录时，应出现的记录返回为空；
2. 财务确认工资批次后，厂长查询本厂工资仍返回为空。

这两个问题属于数据投影或事实源衔接错误，必须先修复，不能通过前端伪造数据、扩大查询范围或建立第二张临时表绕过。

### 3.3 当前占位页面

管理员导航中以下模块尚未形成正式页面：

- 组织架构；
- 角色权限；
- 版本异常；
- DeepSeek 智能服务配置；
- 通知管理；
- 审计日志。

这些路由不得继续由通用“功能建设中”页面作为交付结果。

## 4. 不可破坏的系统边界

### 4.1 单一事实源

| 领域 | 唯一事实源 |
|---|---|
| 员工、角色、工厂 | 现有员工身份与访问档案 |
| Bamboo 生产记录 | `bamboo_records`、`bamboo_stage_submissions` |
| 笼号占用 | `bamboo_cage_occupancies` |
| 生产打回 | `bamboo_returns` |
| 检测窗口与上诉 | `bamboo_inspection_windows`、`bamboo_inspection_exceptions` |
| 厂长通知与知悉 | `mobile_notifications` |
| 人员调动 | `bamboo_personnel_transfers` |
| Bamboo 工资事实 | `bamboo_payroll_facts` 及其正式批次 |
| 电子表单 | `managed_form_definitions`、`managed_form_versions` |
| 表单按厂启用 | `form_plant_activations` |
| 财务账本与更正 | 不可变账本、有效投影和追加式更正记录 |
| 工资规则与计算 | 版本化工资规则、不可变计算批次和正式结果 |
| 报表与导出 | 模板版本、映射版本、导出批次、文件哈希和单元格血缘 |

Web 和移动端不得为相同业务分别维护通知状态、生产状态、工资状态、打回状态或检测状态。

### 4.2 移动端边界

- 不重做 `frontend/apps/web/src/mobile/**` 的工人、主管和检测员界面。
- 不删除或改变移动端现有 API 和 Schema 语义。
- 共享 Schema 只能向后兼容地增加字段，并必须增加契约测试。
- 厂长账户可以登录 Web，但移动 Bamboo 业务入口必须拒绝厂长角色并明确提示使用 Web。
- Managed Form 必须从管理员启用一路贯通到移动端真实填写和提交，不能只在列表中展示。

### 4.3 权限边界

- 普通员工：只查看本人资料、本人业务和本人工资。
- 主管：按既有移动权限处理本厂生产审核和打回。
- 检测员：查看本厂检测队列和只读上游，领取并提交唯一检测或唯一上诉结果。
- 厂长：管理本厂生产处置、人员调动和本厂工资查看，但不得修改表单、流程和工资规则。
- 财务：跨厂查看财务账本、工资明细和汇总，维护财务配置并提交管理员审批。
- 管理员：拥有组织、权限、系统配置、最终审批、按厂启停、历史重算和全局工资查看权。

所有跨厂和工资数据权限必须由后端执行，不能只依赖前端隐藏按钮。

## 5. 第一阶段：修复当前数据闭环

### 5.1 厂长生产投影

- `/api/v1/plant/production` 必须从 Bamboo 生产事实读取当前厂长所属工厂记录。
- 记录的有效状态、当前阶段、笼号、修订号和签字状态必须与移动端读取结果一致。
- 不得读取已经废弃的财务有效记录作为厂长生产看板来源。
- 厂长只能读取本厂；管理员和财务的全局读取不得复用厂长范围校验。

### 5.2 工资正式结果投影

- 财务确认工资批次后，正式工资结果必须能够按员工和工厂映射回 Bamboo 员工身份。
- 厂长查看本厂员工明细和汇总；财务、管理员查看全局；普通员工只查看本人。
- 未确认批次不得出现在正式工资结果。
- 重算产生新批次，不覆盖旧批次；只有再次确认后才成为新的正式结果。
- 查看、筛选、导出和审批工资均写审计。

### 5.3 阶段验收

- 当前两个失败测试修复并通过；
- 本厂与跨厂隔离测试通过；
- 工资确认前后可见性测试通过；
- Web、移动端和后台阶段测试不存在失败或收集错误。

## 6. 第二阶段：完成管理员工作区

### 6.1 组织架构

提供独立的组织架构页面，支持：

- 工厂列表、状态和基本信息；
- 员工搜索、筛选、分页和详情；
- 员工所属工厂、岗位、角色和当前状态；
- 创建员工和分配普通岗位；
- 查看厂内、跨厂人员调动审批链；
- 仅管理员执行厂长任免和调动。

不得直接覆盖员工历史归属。岗位或工厂变化必须形成带生效时间的分配记录和审计事件。

### 6.2 角色权限

- 展示系统固定角色及其权限矩阵；
- 支持管理员授予或撤销允许管理的角色；
- 高权限授予必须二次确认并写审计；
- 禁止形成无管理员系统；
- 禁止厂长授予管理员、财务或厂长角色。

### 6.3 表单审批和生命周期

管理员表单审批页必须完整支持：

- 查看草稿版本、提交人、版本差异和校验结果；
- 同意或驳回，驳回必须填写原因；
- 选择一个或多个工厂启用；
- 查看每个工厂当前启用版本；
- 停用、恢复和退役；
- 发现已有有效版本时明确展示替换影响；
- 每次启停生成持久通知，厂长知悉不阻塞生效。

管理员不能编辑财务提交的表单内容。需要修改时必须驳回，由财务基于原版本复制新草稿。

### 6.4 流程审批和生命周期

流程审批必须具备与表单相同的审批、按厂启用、停用、恢复和退役能力，并在启用前验证：

- 节点和连线完整；
- 起点、终点和可达性有效；
- 节点引用的表单版本可用；
- 角色、工厂和签字权限有效；
- 不存在未处理的阻断级校验错误。

### 6.5 工资规则审批和历史重算

- 查看工资规则版本、公式摘要、适用工厂、岗位、有效期和模拟结果；
- 同意、驳回、失效和替换规则版本；
- 发起指定工厂、人员和期间的历史重算；
- 对比旧批次和新批次差异；
- 重算结果未确认前不进入正式工资；
- 保留规则版本、输入事实、计算过程、舍入和结果血缘。

### 6.6 版本异常

集中展示：

- 表单、流程和工资规则的版本冲突；
- 工厂启用版本不一致；
- 过期客户端提交；
- 失效引用；
- 未完成迁移或投影失败；
- 可重试任务和不可自动修复错误。

管理员只能执行系统明确支持的修复动作，不允许直接修改数据库业务状态。

### 6.7 DeepSeek 配置

- 只显示是否配置、最后测试时间、状态和模型信息，不返回密钥明文；
- 支持新增、替换、删除、启用、停用和连接测试；
- 密钥使用服务器端秘密存储；
- 日志、异常、审计和 API 响应不得出现密钥；
- DeepSeek 只生成建议或草稿，不拥有审批、启用、工资确认和正式数据写入权。

### 6.8 通知管理

- 按类型、接收人、工厂、时间和知悉状态筛选；
- 查看发送、消息中心落库、系统通知尝试和知悉时间；
- 系统弹窗失败不回滚业务事务；
- 管理员可以查看状态，但不能代替用户知悉；
- 通知记录与厂长 Web、移动消息中心使用同一状态。

### 6.9 审计日志

- 按操作者、动作、资源、工厂、时间和请求编号查询；
- 展示操作前提、结果、拒绝原因和关联业务编号；
- 工资审计不得直接在列表暴露无关敏感字段；
- 审计事件不可编辑和删除；
- 支持受控导出审计结果。

## 7. 第三阶段：完善财务工作区

### 7.1 财务账本

今日、月度、年度和异常入口必须形成真实的查询语义，而不是同一无条件列表：

- 今日按服务器北京时间 `submitted_at` 归属；
- 月度和年度支持明确期间选择；
- 支持工厂、表单类型、状态、员工、表号和笼号筛选；
- 支持服务端分页、排序和刷新；
- 详情页展示原始提交、有效投影、更正链、审批、审计和工资影响；
- 异常页只展示待处理、处理中、已关闭等异常状态。

### 7.2 追加式更正

- 原始记录不可覆盖；
- 更正创建新的记录并引用被更正版本；
- 更正原因和证据必填；
- 更正经过财务复核后才更新有效投影；
- 被替换记录、当前有效记录和每次更正永久可追溯；
- 并发复核使用状态前置条件和乐观版本控制。

### 7.3 电子表单设计器

在现有基础字段编辑上补齐：

- 字段分组、标题和说明；
- 文本、数字、日期、时间、单选、多选、人员、工厂、笼号、签字和媒体字段；
- 必填、范围、精度、枚举、最大选择数和格式校验；
- 条件显示和条件必填；
- 只读上游字段；
- 系统带入字段；
- 确定性计算字段；
- 移动端预览；
- 保存草稿、版本差异、复制版本和提交审批。

正式版本不可原地修改。任何修改必须产生新草稿版本。

### 7.4 业务建模

- 支持创建和恢复业务梳理会话；
- 支持输入文字和上传允许的业务材料；
- DeepSeek 输出结构化建议，不直接写正式数据；
- 财务逐条确认业务事实、角色、表单、节点、条件和工资建议；
- 确认后生成不可变业务基线；
- 可从基线生成表单草稿和流程草稿；
- 每次生成均记录输入基线版本和建议版本。

### 7.5 可视化流程设计器

- 使用节点卡片和有向连线表达流程；
- 支持表单、审核、签字、条件、通知和结束节点；
- 支持拖拽、连线、删除、分支条件和节点配置；
- 支持结构校验、模拟运行和错误定位；
- 保存为版本化草稿；
- 提交管理员审批后不可编辑；
- 不在浏览器维护独立于后台的正式流程状态。

### 7.6 工资规则与计算

- 规则编辑采用受限 DSL，不执行任意代码；
- 显示输入事实、单价、奖励、扣减、舍入、封顶和结果；
- 支持样例模拟和错误定位；
- 规则版本提交管理员批准后才可用于正式计算；
- 计算批次冻结规则版本、事实水位和期间；
- 财务确认批次后才形成正式工资。

### 7.7 报表模板、映射与导出

- 管理员上传 `.xls/.xlsx` 并完成安全解析；
- 财务查看模板结构、命名区域、公式和可写区域；
- DeepSeek 只能建议映射；
- 财务可以人工调整并确认映射版本；
- 未确认映射禁止正式导出；
- 日、月、年导出冻结查询条件、模板版本、映射版本和数据水位；
- 导出完成后保存文件哈希和单元格血缘；
- 失败批次不提供半成品下载；
- 历史批次可以按原版本和原水位复现；
- 输出必须通过 WPS 和 Excel 兼容性检查；
- 文本写入必须防止公式注入。

## 8. 第四阶段：完善厂长工作区

### 8.1 生产看板

- 使用中文业务状态，不直接暴露 `SUPERVISOR · ACTIVE` 等内部枚举；
- 支持表号、笼号、员工、工序、状态和日期筛选；
- 支持服务端分页；
- 详情在本工作区内打开；
- 上游表单作为当前页面只读区块展示，不跳转到其他表单页；
- 无修改权限时仍显示完整可见数据，禁止空白页。

### 8.2 独立签字页面

继续沿用原移动端签字流程和设计语义，但页面为厂长 Web 独立路由：

- 展示当前记录、笼号、工序、上游只读信息和检测状态；
- 两小时检测未结束时禁止普通签字；
- 检测合格后立即开放签字；
- 两小时到期后开放签字；
- 两小时内允许“提前结束检测并签字”，必须二次确认；
- 正式签字、提前终止、打回和上诉审批均写审计；
- 重复提交必须幂等；
- 版本冲突返回当前版本并要求刷新。

### 8.3 厂长打回

- 厂长选择一个或多个具体工序打回；
- 原因必填；
- 使用与主管移动端相同的 Bamboo 命令；
- 同时失效受影响的下游签字和工资事实；
- 历史版本、签字和证据只读保留；
- 不得生成第二套 Web 打回状态。

### 8.4 人员调动

人员管理使用独立、适配大屏的页面：

- 厂内调动：厂长提交，管理员批准并执行；
- 跨厂调动：原厂厂长与目标厂厂长均同意，再由管理员批准并执行；
- 任一厂长拒绝后申请关闭，并保存原因；
- 普通员工没有自行申请入口，后台也拒绝员工自助申请；
- 厂长任免和调动只由管理员执行；
- 成功后通知员工和相关厂长；
- 页面展示完整审批链和生效结果。

### 8.5 工资查询

- 首页展示本厂工资汇总；
- 支持按月、员工和岗位筛选；
- 员工详情展示工资构成和计算过程；
- 厂长只能查看本厂；
- 财务和管理员可查看全局；
- 所有访问写审计。

## 9. 检测、笼号和上诉固定规则

这些规则属于既有生产主线，后续 Web 开发不得改变：

### 9.1 笼号

- 占用唯一范围为 `factory_id + cage_no`；
- 同厂有效占用期间禁止再次分选；
- 同一流程的未完成表中不得重复出现同一笼号；
- 关联浸胶和干燥表通过主管审核后立即释放；
- 释放不等待厂长签字；
- 释放后允许新流程复用，历史记录保持不变。

### 9.2 检测

- 检测员默认看到本厂全部待检测表单、表号和笼号，搜索只用于筛选；
- 检测窗口从进入队列起固定两小时，不因领取而重置；
- 第一位领取人取得唯一正式检测资格；
- 一张表最多一份正式检测结果；
- 合格只需点击“检测合格”，不要求填写说明；
- 不合格时文字、照片或录音至少一种；
- 照片和录音必须有明确的记录按钮；
- 检测不合格冻结厂长正常签字。

### 9.3 超时和上诉

- 两小时后关闭普通检测入口；
- 厂长可提前终止检测并签字；
- 超时或提前签字后开放 24 小时上诉；
- 已有领取人时只有该检测员可以上诉；
- 无领取人时第一位领取上诉的本厂检测员取得唯一资格；
- 每张表最多一份上诉检测结果；
- 厂长同意上诉后启动回溯整改，驳回必须填写原因；
- 超过 24 小时不再显示在检测员工作列表，但参与记录永久只读保留。

## 11. 一致性、并发和审计

### 11.1 事务

以下动作必须在单一数据库事务内完成：

- 笼号占用和释放；
- 正式表单提交及账本投影事件；
- 检测领取和上诉领取；
- 厂长或主管打回及下游失效；
- 人员调动状态变化和最终执行；
- 工资批次确认和正式结果切换；
- 表单或流程按厂启停和通知落库。

### 11.2 幂等与乐观并发

- 可重试写请求携带 `Idempotency-Key`；
- 相同键和相同载荷返回第一次结果；
- 相同键和不同载荷返回 `IDEMPOTENCY_CONFLICT`；
- 状态转换携带预期修订号；
- 修订号不一致返回 `REVISION_CONFLICT`；
- 前端收到冲突后刷新服务端状态，不得在本地伪造成功。

### 11.3 审计

登录失败、越权、审批、启停、签字、打回、检测、上诉、调动、工资查看、工资确认、历史重算、模板上传、映射确认、导出和下载均写不可变审计事件。

## 12. 旧识别链路退役

旧照片导入、OCR、OMR、自动填充、图片复核和重拍不再属于产品主线。

完成新链路对应能力后，按依赖顺序退役：

1. 移除旧导航和 Web 路由；
2. 移除仅服务旧识别的 API；
3. 移除 `RecognizeForms`、`ReviewForms`、`AIReviewForms` 和 OpenCV 识别服务装配；
4. 移除旧后台任务和只服务旧流程的适配器；
5. 通过新 Alembic 迁移归档或删除确认无历史业务数据的结构；
6. 保留仍被电子表单、报表、审计或 Bamboo 主线使用的通用文件能力。

删除前必须执行依赖扫描、数据库备份、历史行数报告和恢复演练。不得修改历史迁移文件。

## 13. 前端交互标准

- 三个工作区保持统一视觉框架、导航、加载、错误和空状态；
- 内部状态统一翻译为中文；
- 禁止使用浏览器原生简陋提示框完成正式审批；
- 破坏性或不可逆操作使用明确的二次确认；
- 大列表使用服务端分页和筛选；
- 详情页保留返回路径和当前筛选条件；
- 无权限时显示明确原因或只读内容，不显示空白页面；
- Android PWA 安装优先调用浏览器安装事件；不支持时展示简短的对应浏览器操作指引；
- 浏览器和 Android 系统要求的安装确认不能绕过，不承诺所有浏览器真正无确认一键创建桌面图标。

## 15. 实施顺序

必须按以下顺序推进，每一阶段独立提交和验收：

1. 修复厂长生产和工资两个数据闭环错误；
2. 完成管理员组织、角色、版本异常、智能服务、通知和审计；
3. 完成管理员表单、流程、工资全生命周期；
4. 完善财务账本、更正和详情；
5. 完善财务表单设计、业务建模和可视化流程；
6. 完善工资规则、历史重算、报表映射和导出；
7. 完善厂长生产、人员和工资页面；
8. 完成全量测试、旧识别退役、迁移和生产部署检查。

不得为了页面进度跳过后台权限、事务、审计和契约测试。

## 16. 最终验收标准

只有同时满足以下条件，才能把该版本标记为允许生产部署：

1. 管理员导航不存在“功能建设中”占位模块；
2. 财务今日、月度、年度和异常页面具有真实独立查询语义；
3. 表单设计、流程设计和业务建模能够形成受控版本并完成管理员审批；
4. 表单和流程按厂启用、停用、恢复、退役及通知知悉闭环完整；
5. 厂长生产、签字、打回、检测上诉、人员调动和工资功能使用 Bamboo 单一事实源；
6. 厂长与主管并发打回具备幂等和版本冲突保护；
7. 笼号、检测窗口、唯一检测和 24 小时上诉规则全部由后台强制执行；
8. 厂内和跨厂调动审批链符合最终确认规则；
9. 普通员工、厂长、财务和管理员工资权限及审计全部正确；
10. 工资历史重算不覆盖旧结果，正式结果必须经过确认；
11. 报表映射必须人工确认，导出可复现并具有数据水位、文件哈希和单元格血缘；
12. DeepSeek 无正式审批权和不可逆执行权，密钥不可读取；
13. 移动端现有工人、主管、检测员流程和 API 契约无回归；
14. 旧识别入口、服务装配和无用数据库结构完成受控退役；
15. Python、迁移、API、TypeScript、Vitest、构建、集成、安全和端到端测试全量通过；
16. 使用真实 Android 手机、主流浏览器、WPS 和 Excel 完成人工验收；
17. 完成数据库备份恢复、HTTPS 服务器部署和回滚演练；
18. 验收报告中的结果与实际测试输出一致，不再使用阶段性测试代替最终验收。

## 17. 非目标

- 不重写 Bamboo 工序状态机；
- 不建立第二套 Web 生产、通知、工资或人员调动状态；
- 不恢复厂长移动端 Bamboo 业务；
- 不让厂长审批表单、流程或工资规则；
- 不允许 DeepSeek 直接修改或批准正式业务数据；
- 不因界面开发修改工人、主管和检测员已经冻结的移动交互；
- 不在本轮引入与三工作区闭环无关的新业务模块。

## 18. 结论

后续开发以“先修复真实数据闭环，再补齐管理员，再完善财务与厂长，最后退役旧链路和全量验收”为唯一主线。

每项功能必须同时具备页面、API、权限、事务、审计和测试。仅有页面、仅有接口、仅有测试桩或仅能展示演示数据，均不视为完成。
