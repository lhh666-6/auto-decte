# 竹丝工序记录 V3 正式工程设计

日期：2026-07-22  
状态：已批准进入实施  
依据：`竹丝工序记录-原型V3(1).html`、`竹丝工序记录-原型V3-工程交接.md` 与 2026-07-22 需求确认

## 1. 目标与范围

本项目把单文件演示原型升级为正式的多厂移动端 PWA 流程。正式实现必须保留原型的移动体验，同时把身份、权限、流程、工资、签字、检测证据、审核、财务审批和更正迁移到后端领域模型。

本轮包含：

- 多厂组织隔离与可扩展工种目录。
- 分选、浸胶、干燥装架、主管、检测、厂长审核和财务审批。
- 预建任务与现场新建两种记录来源。
- 严格按流程开放的任务可见性。
- 分选工资和浸胶/干燥联合工资事实。
- 多次检测及照片、录音、文字留痕。
- 选择性退回、版本失效、更正链和不可覆盖审计。
- 单日 XLSX 审批批次与已审批数据的月度汇总。
- 财务穿透原表、向厂长询问、部分放行和补充批次。
- 移动端首页、任务列表、完整电子表单、草稿、提交记录和个人中心。

本轮不包含网页端管理员界面的完整视觉重做。后端仍需提供工厂、任命和身份审批能力，以便后续网页端接入。

## 2. 设计原则

1. 流程合法性、权限、签字时间和工资生效均由后端决定。
2. 已签字内容不可原地修改；更正创建新版本和调整记录。
3. 页面是否可见与动作是否可执行分别由后端授权，前端隐藏不能代替鉴权。
4. 工厂和工种使用目录数据，不把未来工厂、工种或中文名称写死在流程代码里。
5. 竹丝生产记录与工资事实共享录入来源，但拥有独立状态和审计生命周期。
6. 离线只允许保存草稿；签字、退回、审核、询问和财务审批必须联网。
7. 沿用现有 PWA、登录会话、草稿/待上传基础设施、主数据和 XLSX 导出能力。

## 3. 多厂组织与身份

### 3.1 权限层级

| 层级 | 身份 | 权限 |
|---|---|---|
| 管理层 | 系统管理员 | 创建/停用工厂、跨厂调动、任命厂长和财务、跨厂审计 |
| 审核层 | 厂长 | 本厂审核人；任命主管/检测；审批普通工种切换；本厂汇总 |
| 监督层 | 主管 | 查看完整生产表、评价、关闭检测异常、选择性退回 |
| 监督层 | 检测人 | 查看已开放完整表、新增检测及证据 |
| 生产层 | 分选人 | 新建或处理分选/装笼任务，生成分选工资事实 |
| 生产层 | 浸胶人 | 处理浸胶分区并签字 |
| 生产层 | 干燥装架人 | 处理干燥分区并签字，完成联合节点 |
| 财务层 | 财务审批人 | 审批单日导出条目、回溯原表、询问厂长、发起更正 |

### 3.2 新人和身份变更

- 管理员或人事创建账号并确定所属工厂。
- 新账号初始为 `PENDING_ROLE`，可登录查看状态但不能领取任务。
- 所属厂厂长确定初始普通工种，或主动任命主管/检测。
- 普通员工只可申请在分选、浸胶、干燥装架之间切换。
- 主管和检测由厂长主动任命；厂长和财务由管理员任命。
- 每名员工同一时间只有一个所属工厂和一个有效竹丝身份。
- 跨厂调动由管理员处理；历史记录保留提交时的工厂和身份快照。

### 3.3 可扩展目录

`BambooRoleDefinition` 保存稳定编码、显示名称、类别、可申请性和状态。初始工种编码为：

- `SORT_OPERATOR`
- `DIPPING_OPERATOR`
- `DRYING_RACK_OPERATOR`
- `INSPECTOR`
- `SUPERVISOR`
- `PLANT_MANAGER`
- `FINANCE_APPROVER`
- `SYSTEM_ADMIN`

新增工种通过目录和流程定义接入，不修改历史角色快照。

## 4. 业务流程与可见性

### 4.1 主流程

```text
预建任务 / 现场新建
  → 分选/装笼填写并签字
  → 浸胶填写并签字
  → 干燥装架填写并签字
  → 浸胶+干燥联合节点完成
  → 主管核对、评价和异常闭环
  → 厂长审核签字
  → 表单与待生效工资正式生效
  → 进入单日 XLSX 批次
  → 财务逐条审批
  → 已审批条目进入月度汇总
```

### 4.2 严格分层可见性

- 分选任务只对本厂分选人开放。
- 分选签字后，浸胶人才看到记录。
- 浸胶签字后，干燥装架人才看到记录。
- 浸胶和干燥双方均签字后，主管与检测人才看到完整电子表单。
- 主管完成、检测窗口关闭且所有异常已闭环后，厂长才可打开具体表单审核。
- 厂长在此前只能看本厂各阶段汇总数量，不能打开未到审核阶段的具体表单。
- 财务只看到厂长审核后形成的单日批次；可从批次条目穿透只读原表。
- 管理员可跨厂审计，但不能直接编辑已签字生产数据。
- 未授权记录不出现在列表中，直接访问详情也返回 `403` 或 `404`，避免泄露存在性。

### 4.3 签字

签字采用已确认的 C 方案：用户在手机屏幕上手写签名，前端将签名图像上传为不可变证据文件，后端在当前登录会话中生成电子签名记录。签名保存：

- 签字人内部 ID、工号和姓名快照。
- 签字时有效身份与所属工厂快照。
- 服务端签字时间。
- 被签数据的规范化摘要与 SHA-256 哈希。
- 手写签名文件 ID、MIME、文件哈希和存储位置引用；数据库不保存可变的临时画布数据。
- 记录版本和客户端幂等键。
- 设备 ID、请求 ID 和可选客户端版本。

签字前前端显示确认摘要和签名画布；空白签名不得提交。签字图像必须在联网状态下上传成功后才能完成签字，签字后数据和签名文件均不可原地修改。

## 5. 竹丝表单与工资事实

### 5.1 分选/装笼

字段沿用 V3：作业类型、特殊类、长度、深浅、品级、供应商、笼号、把数、净重和含水率检测点。

- 净重按版本化规则计算：2.1m × 5、2.3m × 6、2.5m × 7，初始值来自交接文档。
- 分选提交并签字时，在同一事务中创建 `SORT` 工资事实。
- 工资金额立即计算并锁定，状态为 `PENDING_EFFECTIVE`。
- 后续工序复用分选基础信息，不重复录入。

### 5.2 浸胶与干燥装架联合节点

- 浸胶和干燥保留各自字段、操作人、版本和签字。
- 浸胶字段：胶前重、胶后重、上胶量、含水率。
- 干燥字段：含水率、一个或多个不重复的干燥架号。
- 两位操作人必须分别签字；缺少任何一方，联合节点不完成。
- 联合节点完成时创建一条关联工资记录，分别保存浸胶人和干燥装架人的金额分配。
- 工资规则采用“系统默认 + 工厂覆盖”，每次计算保存具体规则版本和输入快照。

### 5.3 工资生效与调整

- 厂长审核前，工资事实均为 `PENDING_EFFECTIVE`。
- 厂长审核签字时，当前有效工资版本转为 `EFFECTIVE`。
- 更正影响工资字段时创建新工资版本和差额调整，不覆盖原工资事实。
- 导出条目引用具体工资事实版本，保证历史 XLSX 可复现。

## 6. 检测与证据

- 检测人在联合生产节点完成后自主选择记录。
- 每次检测自行填写检测序号，并选择目标工序：分选、浸胶或干燥装架。
- 同一记录允许多次检测、不同工序检测和复测。
- 检测保存含水率点、平均值、结论、说明和独立签字。
- 结论为“不合格”或“需复测”时创建异常任务。
- 异常不立即冻结正在完成的生产数据，但主管签字前必须关闭异常或存在合格复测。
- 主管签字会原子关闭当前版本的检测窗口；之后不能向该版本追加检测。

证据支持照片、录音和文字组合：

- 元数据保存文件 ID、MIME、大小、哈希、上传人、服务端时间和目标检测记录。
- 文件存储通过端口抽象，开发环境可使用本地文件适配器，生产可切对象存储。
- 离线草稿可在 IndexedDB 暂存附件；正式提交前必须联网完成上传。
- 初始可配置限制：最多 6 张照片、单段录音最多 3 分钟、文字最多 1000 字。限制由服务端配置返回。

## 7. 主管、厂长和选择性退回

### 7.1 完整表单只读视图

主管、检测和厂长在流程开放后可查看：

- 公共基础信息和工资计算依据。
- 三道生产工序的当前有效版本、签字人与历史版本。
- 分选工资与联合工资的计算摘要和状态。
- 所有检测记录、证据和异常处理。
- 主管评价、退回原因、厂长审核和更正链。

角色只可编辑自己的操作区，不能直接修改工人数据。

### 7.2 选择性退回

- 主管退回时勾选真正需要重写的生产工序并填写必填原因。
- 未选中的工序版本继续有效，减少冗余操作。
- 被选工序及依赖其数据的签字、工资版本和下游确认标记为 `INVALIDATED`。
- 审核或财务发现问题时不直接选择生产工序，而是先退回主管，由主管判断影响范围。
- 每次重提生成递增版本，旧版本只读保留。

依赖规则由后端状态机集中维护。例如退回浸胶默认使干燥联合确认、主管确认和厂长审核失效；主管可保留与浸胶无依赖的分选版本。

### 7.3 厂长审核时间门槛

主管签字到厂长审核之间的等待时间由后端配置；生产默认 12 小时，测试环境可缩短。服务端返回最早可审核时间和剩余时间，禁止依赖客户端时钟。

## 8. 财务批次、回溯与月度汇总

### 8.1 单日批次

- 按工厂、业务日期和批次版本生成单日 XLSX。
- 每条工资事实形成独立批次条目。
- 批次条目状态：`PENDING`、`APPROVED`、`HELD`、`CORRECTION_REQUIRED`、`SUPERSEDED`。
- 财务逐条审批，无问题条目可先通过。
- 有疑问条目进入暂缓清单，解决后进入补充批次，不阻塞其余人员工资。

### 8.2 穿透回溯与询问

- 财务从 XLSX 行或批次条目回到对应原始电子表单。
- 财务拥有完整只读视图，包括所有签字、检测证据、工资规则版本和更正历史。
- 财务可以向所属厂厂长发起询问，关联具体字段、工资行或版本。
- 厂长在系统内回复；问题、回复、人员和服务端时间均不可删除。
- 财务不能直接修改生产数据。

### 8.3 财务更正

- 确认错误后创建 `CorrectionCase`，保留原生效表单、原工资事实和原 XLSX。
- 更正返回主管，由主管选择需要重写的工序。
- 新版本重新经过主管与厂长签字，生成工资调整和补充导出批次。
- 原批次条目标记已被更正版替代，但仍可下载和审计。

### 8.4 月度汇总

- 按工厂和月份汇总已获财务批准的单日批次条目。
- 暂缓、待更正和已替代条目不进入当前月度有效汇总。
- 月度文件保留生成时间、查询范围、来源批次和条目版本集合。

## 9. 领域模型与持久化

建议新增独立模块 `app/modules/bamboo_process/`，核心实体：

|---|---|

| `PayrollFact` | 分选或联合工资事实及版本 |
| `InspectionRecord` | 多次检测和复测 |

## 12. 离线、并发与错误处理

### 12.1 离线

- 表单输入、检测文字和待上传附件可保存在 IndexedDB 草稿。
- 离线时签字、退回、审核、询问和财务审批按钮明确禁用。
- 恢复在线后先刷新服务端 revision；若流程已变化，保留草稿并展示差异，不自动覆盖。

### 12.2 标准错误

| HTTP | 代码 | 前端处理 |
|---|---|---|
| 401 | `SESSION_EXPIRED` | 清除会话并返回登录页 |
| 403/404 | `RECORD_NOT_VISIBLE` | 返回任务列表，不泄露记录详情 |
| 409 | `STALE_REVISION` | 刷新记录，展示冲突摘要并保留草稿 |
| 409 | `STAGE_NOT_AVAILABLE` | 提示流程已变化，禁止重复签字 |
| 409 | `OPEN_INSPECTION_EXCEPTION` | 定位未关闭异常 |
| 422 | `FIELD_VALIDATION_FAILED` | 字段级错误及首错定位 |
| 423 | `AUDIT_WAIT_NOT_ELAPSED` | 显示服务端最早审核时间 |
| 503 | `EVIDENCE_STORAGE_UNAVAILABLE` | 保留草稿和附件，允许稍后重试 |

## 13. 测试与验收

### 13.1 后端

- 状态机单元测试覆盖全部合法/非法转换。
- 权限矩阵覆盖跨厂访问、未轮到记录、身份变更和历史快照。
- 工资规则版本、工厂覆盖、锁定、生效和差额调整测试。
- 联合签字并发测试：两人提交顺序任意但只完成一次联合节点。
- 选择性退回测试：仅目标及真实依赖失效。
- 检测异常、复测和主管关闭门槛测试。
- 厂长等待时间使用可控时钟测试。
- 导出快照、部分批准、暂缓、询问、补充批次和月度汇总测试。
- 幂等、乐观锁、跨事务原子性和数据库迁移回滚测试。

### 13.2 前端

- 页面路由和身份可见性组件测试。
- 含水率、架号、工资摘要和确认 Sheet 交互测试。
- 离线草稿、恢复、冲突和附件暂存测试。
- 主管/检测/厂长完整表单只读与专属操作区测试。
- 财务穿透原表、询问和部分批准测试。
- 320、375、390、430、520px 视口无页面级横向溢出。
- 键盘、焦点、44px 触控、16px 输入和安全区检查。

### 13.3 端到端角色回归

至少覆盖：

1. 现场新建 → 分选工资锁定 → 浸胶/干燥双签 → 主管 → 厂长 → 单日批次 → 财务通过。
2. 预建任务完整流程。
3. 检测不合格 → 主管关闭/复测 → 厂长审核。
4. 主管选择性退回一个工序，未选工序不重复填写。
5. 财务暂缓一条、放行其余、询问厂长并生成补充批次。
6. 更正后原表、原工资和原 XLSX 仍可回溯。
7. 普通员工申请切换工种并由厂长批准。
8. 新员工待分配职务不能领取任务。
9. 跨厂访问被阻止。

## 14. 实施边界与迁移策略

实施采用专用竹丝领域模块，复用现有通用电子表单和 PWA 基础设施，不把完整状态机塞入通用 `values` JSON。

推荐增量顺序：

1. 工厂、身份目录和竹丝领域基础模型。
2. 主流程状态机、严格可见性和不可变工序版本。
3. 分选工资与浸胶/干燥联合签字工资。
4. 检测、证据和异常闭环。
5. 主管、厂长审核和选择性退回。
6. 移动端任务列表、详情和各角色操作区。
7. 单日批次、财务回溯/询问、部分批准和月度汇总。
8. 全链路真机、权限、并发和迁移验证。

现有 `MobileBambooProcessPage` 的三步演示实现将被逐步替换；现有登录、会话、草稿、提交记录和 PWA Shell 保留并扩展。

## 15. 已确认默认值

- 架构方案：专用竹丝领域模块，复用共享平台能力。
- 任务归属：本厂同岗位公共任务池。
- 退回：主管选择真正需要重写的工序。
- 审核：厂长即审核人，主管签字后默认等待 12 小时，可配置。
- 离线：只保存草稿，流程动作必须在线。
- 记录来源：预建任务与现场新建并存。
- 身份：单一当前身份、单一所属工厂，目录可扩展。
- 检测：检测人自主选择、多次检测、多媒体留痕；异常需闭环。
- 生效点：厂长审核签字。
- 财务：审批单日条目，支持穿透询问、部分放行和补充批次。
- 工资：分选签字锁定分选工资；浸胶/干燥双签后分别锁定两人工资；厂长审核后生效。
- 签字：手机屏幕手写签名，绑定当前登录身份、签名文件哈希和被签数据哈希。
