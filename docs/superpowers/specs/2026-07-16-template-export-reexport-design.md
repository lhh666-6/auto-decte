# 模板化导出与重导闭环设计

## 目标与边界

本阶段把现有同步四工作表导出升级为模板驱动、可预览、可追溯、可授权下载、可重导的产品闭环。实现只扩展 reporting、tasks、exports API、API Client 和 React 导出中心；不改变模板发布、识别、审核事务、主数据、历史迁移或桌面壳语义。

## 采用方案

采用“专用导出应用服务 + 复用通用任务状态机”的方案：

- `ReportingFacade` 负责预览、批次查询和调用导出执行器。
- `ExportHandler` 消费 `XLSX_EXPORT` 任务，更新现有 Task/SSE 进度。
- `ExportForms` 负责最终校验、模板映射、原子文件生成、批次落库和表单状态更新。
- `XlsxExporter` 只负责根据不可变映射快照写入工作簿，并统一转义潜在公式文本。
- `exports_ds` Router 负责导出专用权限、幂等提交、批次读取和受控下载；浏览器永远看不到内部路径。

不采用以下替代方案：

1. 不在通用 `/tasks` 创建接口中拼装导出业务，因为它无法表达导出权限、最终校验和批次语义。
2. 不新增第二套任务表或前端直写文件，因为会绕开现有状态机、SSE 和 Web/Tauri 边界。
3. 不覆盖旧导出文件或旧批次，因为会破坏审计与重导追溯。

## 领域与持久化模型

`ExportBatch` 扩展为成功导出的不可变事实，保存：

- 批次编号、导出类型和成功状态；
- 模板版本快照；
- `ExportTarget` 映射快照及稳定的映射哈希；
- 筛选快照；
- 已包含的 `(form_id, record_version)`；
- 内部文件路径、对外下载文件名和 SHA-256；
- 操作者与时间；
- 可选 `supersedes_batch_id`。

迁移只新增 `007_export_batches_ds.py`。旧批次列保留并补充新列，应用的自动建库模型同步更新。Repository 增加按编号读取和倒序列表能力，不向 API 直接暴露 ORM 或 `file_path`。

预览使用结构化结果：`included`、`excluded`、字段/表单级原因和映射摘要。候选表单先按请求筛选，再验证当前记录、审核状态、模板版本、模板发布状态、字段规则和导出映射。预览不创建任务、批次或文件。

## 数据流与失败语义

### 预览

1. Router 校验 `EXPORT_PREVIEW`。
2. Reporting 服务读取候选表单和对应不可变模板版本。
3. 最终校验器将记录分为包含与排除，并生成原因。
4. API 返回安全 DTO，不生成文件或修改状态。

### 创建导出

1. Router 校验 `EXPORT_CREATE` 和 `Idempotency-Key`。
2. 使用固定资源范围 `EXPORTS` 提交 `XLSX_EXPORT` Task，使同一操作者、同一幂等键、不同 payload 能稳定冲突。
3. 返回 `202`、`task_id`、状态 URL 和 SSE URL。
4. Handler 将任务切换为 RUNNING，重新执行最终校验，写入同目录临时文件。
5. 文件成功关闭后计算哈希；数据库事务写入批次、审计和表单导出状态。
6. 临时文件以原子替换发布为最终文件，任务标记 SUCCEEDED。

任何异常都删除临时文件；未完成全部数据库事实前不得存在成功批次。若数据库提交失败，最终文件也必须清理。任务标记 FAILED，并保留错误摘要供状态接口读取。

### 更正与重导

审核更正继续沿用现有 `REEXPORT_REQUIRED` 行为。重导请求必须显式提供被替代批次；新批次重新捕获当前记录与映射快照，生成不同文件，并将 `supersedes_batch_id` 指向旧批次。旧批次和文件保持不变。

## 安全与权限

- `OPERATOR` 不获得任何导出权限。
- `FINANCE` 保留预览和创建权限，并获得最小的 `EXPORT_DOWNLOAD` 权限。
- 通用任务读取继续使用现有策略；导出 API 只允许创建者或具备相应导出权限的身份读取导出任务进度，避免给 FINANCE 开放全部任务。
- 下载通过批次 ID 定位内部文件，并以 `FileResponse` 返回安全文件名；批次 JSON 永不返回路径或内部 URI。
- 任意字符串在去除 Unicode BOM 后若以 `=`, `+`, `-`, `@` 开头，写入 XLSX 前加单引号；数字、日期和布尔值保持原类型。

## React 导出中心

新增独立 `ExportCenter` Feature，并由现有“可导出”入口进入。页面只通过 API Client 访问：

- 筛选与预览；
- 包含/排除记录和原因；
- 创建任务并轮询状态/SSE；
- 批次历史与下载；
- `REEXPORT_REQUIRED` 提示和显式重导动作。

组件不访问本地路径、数据库或 Tauri API。退出导出中心回到审核工作台，不改变审核中的未保存修改保护。

## 验证策略

测试按以下层次建立：

1. XLSX 单元/集成测试：模板映射、追溯列、公式防护、旧文件保留。
2. Reporting/Handler 测试：预览排除、最终校验、进度、成功批次、失败清理、重导关联。
3. API 测试：权限、幂等、`202` 契约、列表/详情、受控下载和路径不泄露。
4. 前端契约测试：请求、响应、错误处理和下载；组件测试覆盖预览、任务进度、历史和重导提示。
5. 全量 Python、Ruff、mypy、前端测试、类型检查与生产构建。
6. 浏览器人工闭环：预览 → 创建 → 成功 → 下载 → 更正 → 需重导 → 重导 → 验证旧文件和替代关系。
