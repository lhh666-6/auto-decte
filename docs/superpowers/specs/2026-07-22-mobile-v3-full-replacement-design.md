# 移动端 V3 完整替换设计

## 1. 目标

以以下两份交付物作为移动端界面和交互的唯一产品基线：

- `竹丝工序记录-原型V3(1).html`
- `竹丝工序记录-原型V3-工程交接.md`

正式工程使用 React、现有移动 API、Cookie 会话和 PWA 能力实现原型，不复制原型内的演示状态。旧通用移动端首页、旧记录入口、旧五栏导航和旧蓝灰视觉全部退出产品界面，只保留 V3。

## 2. 替换边界

### 删除或退出路由的旧界面

- `MobileHomePage` 旧通用表单首页。
- `MobileRecordPage` 旧通用记录选择页。
- 独立的旧 `MobileDraftsPage`、`MobileOutboxPage` 导航入口。
- 旧五栏底部导航及 Emoji 图标。
- 旧蓝灰移动端主题和无限宽移动外壳。

旧组件若仍被桌面端测试或历史代码引用，可以在迁移期间保留源码，但不得出现在任何正式 `/mobile/*` 路由中。完成验收后删除无引用组件。

### 必须保留的工程能力

- Cookie 登录、CSRF、幂等键和工厂隔离。
- 离线草稿与待同步队列；只允许草稿离线，正式签字必须联网。
- 分选、浸胶、干燥、检测、主管、厂长、财务全部正式业务 API。
- PWA 安装、缓存更新提示和安全区适配。

## 3. 唯一移动端信息架构

移动端底部固定四栏，与 V3 原型一致：

1. **首页** `/mobile/home`
   - V3 绿色顶部区域、当前人员与工厂信息、联网状态。
   - 可处理、等待中、已完成三项统计。
   - 依职务显示快捷入口；不再显示通用“可填写表单”。
2. **记录工作** `/mobile/work`
   - 可记录、等待上游、已完成三个标签。
   - 使用 V3 记录卡片、状态胶囊和未读提示。
   - 记录详情 `/mobile/records/:recordId`。
3. **提交记录** `/mobile/submissions`
   - 当前用户的正式签字、草稿和待同步记录在同一页面分组呈现。
   - 草稿和待同步不再占用底部导航栏。
4. **我的** `/mobile/profile`
   - 人员、工厂、职务、网络、PWA 版本和退出登录。
   - 生产工人的换岗申请从此页进入；厂长和管理员显示人员配置入口。

兼容跳转：旧 `/mobile/record/bamboo-process`、`/mobile/record/bamboo-process/:id`、`/mobile/record`、`/mobile/drafts` 和 `/mobile/outbox` 使用 `Navigate replace` 跳转到对应 V3 页面，不再渲染旧界面。

## 4. 登录与角色落点

- 登录页改用 V3 绿色品牌视觉，不再使用旧深蓝登录页。
- 竹丝职务账号登录成功后进入 `/mobile/home`，该地址本身就是 V3 首页，而非旧通用首页。
- 没有竹丝职务的账号显示“等待管理员/厂长分配职务”，不得进入生产记录。
- 首页和记录工作页根据正式会话中的 `bamboo_role` 渲染，不提供原型的身份演示切换器。

## 5. 视觉约束

- 页面内容最大宽度 `520px`，桌面浏览器中居中模拟手机，背景不横向拉伸。
- 主色采用原型 `#17653a`，辅助绿色 `#26804d`，页面背景 `#f3f5f4`。
- 使用 `100dvh`、`viewport-fit=cover` 和安全区变量。
- 固定四栏底部导航；使用统一 SVG 图标，不使用 Emoji。
- 常规触控区最小高度 `44px`，表单输入字号至少 `16px`。
- 流程条和标签栏允许容器内横向滚动，页面不得产生横向溢出。
- 详情、签字确认、检测留痕、选择性回退和财务询问采用 V3 Bottom Sheet/卡片语言。
- 所有中文必须直接以 UTF-8 源码保存；禁止双重编码字符串和 `???` 占位。

## 6. 页面与业务映射

### 记录详情

- 顶部显示记录编号、当前状态和流程条。
- 主管、检测人、厂长看到已开放的整张电子表单。
- 未开放环节以锁定状态显示，不提前暴露可操作表单。
- 各工序签字以版本卡片展示；失效历史保留但折叠显示。

### 角色操作

- 分选：创建记录、填写分选数据和工资，确认签字后锁定。
- 浸胶、干燥：分别填报、分别签字；界面明确提示联合工资关系。
- 检测：自行填写检测序号，选择前三个流程，添加照片、录音或文字留痕。
- 主管：处理检测异常、评价前三道工序、选择需要重写的环节。
- 厂长：查看等待时间、审核、处理换岗与人员分配、回复财务询问。
- 财务：逐条批准/暂缓/纠错，查看原始表单，单日/月度导出。

## 8. PWA 更新策略

- 提升前端缓存版本并清理旧移动端导航和页面资源。
- 开发环境注销已注册 Service Worker，避免 Vite 被旧缓存拦截。
- 生产环境发现新版本后显示更新提示，用户确认后执行 `skipWaiting`、刷新并加载 V3。

## 9. 测试与验收

测试先行，并至少覆盖：

- 竹丝账号登录后只进入 V3 首页。
- 底部只存在：首页、记录工作、提交记录、我的。
- 旧路由只跳转，不渲染旧组件。
- 520px 容器、绿色主题和非 Emoji 图标。
- 七个演示账号返回正确中文姓名、工厂和职位。
- 各角色只看到其被开放的操作。
- 草稿/待同步仍可访问，但不作为独立导航栏。
- Service Worker 更新后不再返回旧首页。
- 全量前后端测试和 PWA 生产构建通过。

## 10. 验收定义

在 `http://localhost:5173/mobile/login` 使用任一竹丝演示账号登录后：

1. 不再看到截图中的旧通用首页。
2. 不出现 `???`、乱码或 Emoji 导航。
3. 桌面窗口中界面保持 520px 手机宽度并居中。
4. 页面结构、颜色、卡片、流程条和四栏导航与 V3 原型一致。
5. 所有正式业务功能继续使用现有后端数据与权限，不退回浏览器演示数据。
