# 模板驱动纸质表单闭环设计

## 1. 目标

将现有的“图片导入后人工审核”链路升级为模板驱动的纸质表单闭环：管理员重新设计并打印纸质表单；每张表单图片通过专属模板标识自动分类；系统依模板裁切、识别并按置信度自动填入；人工只处理低置信度、缺失或规则异常项；最终按模板映射导出可追溯 XLSX。

该设计不将模板选择留给现场工人。工人只使用已经发布的纸质表单，上传或拍摄填写后的图片。

## 2. 不可变原则

- 每个模板版本有唯一、可打印、可校验的二维码标识；二维码只标识模板，不携带员工、工单、数量或其他业务数据。
- 模板版本发布后不可编辑。调优必须复制为新版本；已导入的表单永久绑定导入时解析出的模板版本和坐标版本。
- QR 分类成功后，识别器只能使用对应模板的字段坐标、字段类型、识别策略、阈值、规则和导出映射。
- 自动识别结果是候选值，不覆盖人工事实。只有高置信度且通过字段级门槛的候选可以预填；最终确认仍写入新的 `RecordVersion` 与审计事件。
- 证据、裁切、模板包和导出批次均通过受控 API 访问，不向浏览器返回数据库对象、服务器绝对路径或存储 `uri`。
- 设计遵循现有模块化单体、SQLite 和本地证据基线；未来存储、任务执行器与数据库只能经 Port/Adapter 替换。

## 3. 模板包

一个模板包是可导入、可导出、可版本化的目录或 ZIP，包含：

```text
manifest.json        模板身份、版本、校验和、页面尺寸和状态
form-background.png  可打印空白纸质表单背景
layout.json          字段、坐标、字段类型、识别与规则配置
export-map.json      字段到 XLSX 业务列的映射
preview.png          模板预览图
```

`manifest.json` 的模板标识格式固定为：

```text
IFD|<template_key>|<version>|<checksum>
```

示例：`IFD|PROD_DAILY|3|A17C`。`template_key` 使用大写 ASCII、数字与下划线；`version` 为正整数；`checksum` 校验模板键与版本，防止误读和人为录入错误。

设计器在发布时自动生成该二维码，并在表单上放置四个高对比度定位标记。二维码是分类依据；定位标记用于拍照后的透视校正。二维码无法读取时，导入任务进入“待分类”队列，由有权限的操作员选择已发布模板；该人工选择被审计。

## 4. 设计器与模板生命周期

模板中心包含“模板库、设计器、版本历史、导入/导出模板包”四个界面。

1. 管理员可上传旧的空白纸质表单扫描图作为底稿，或从空白 A4/A5 画布开始设计。
2. 在画布上放置固定文本、表格线、字段、二维码和四角定位标记。
3. 每个字段配置：稳定 `field_key`、显示名、数据类型、坐标、识别引擎、最低自动填充置信度、必填/范围/主数据/数量闭合规则、是否允许异常说明、导出列。
4. 设计器显示二维码与定位标记的不可覆盖安全区，阻止字段与安全区重叠。
5. 设计完成后进行模板预检：所有导出字段有映射、字段坐标在页面内、二维码/定位标记存在、规则引用的字段存在、字段键唯一。
6. 通过预检后发布新版本，并导出可打印 PNG/PDF 和模板包 ZIP。
7. 已发布模板只能“复制并调优”。新版本保留父版本引用，旧版本可阅读、导出、追溯但不可再用于新设计修改。

预置的 3–4 个通用模板仅作为设计器的示例起点，不替代企业专属模板：生产日报、工序检验、物料流转、异常返工。

## 5. 图片导入与自动填充

```text
图片上传/相机采集
  → SHA-256 去重和不可变原图证据
  → 图像质量检查
  → QR 读取
  → 模板版本匹配
  → 定位标记/透视校正
  → 按模板字段坐标裁切
  → OCR / 数字 / OMR 候选
  → 每字段置信度与规则预检
  → 自动预填或进入人工审核队列
```

导入 API 接收受控的文件上传和可选来源信息，不接受浏览器传入的服务器路径。它创建持久化 `FORM_IMPORT` 任务并返回任务状态 URL/SSE URL。任务只允许白名单操作；实际文件、模板解析、识别和导出均由服务端 Handler 执行。

自动填充判定规则：

- 字段候选必须是该模板声明的识别引擎输出，置信度不低于该字段阈值；
- 数据类型、范围、主数据和跨字段闭合规则必须通过；
- 满足条件的值标记为 `AUTO_APPROVED` 候选并在审核页以绿色预填显示；
- 不满足条件的字段以黄色“待确认”显示；阻断性规则错误以红色显示；
- 无论自动填充数多少，表单仍进入审核队列，直到具有审核权限的人确认、退回或作废。

## 6. 人工审核与队列

审核工作台保留“左图右表”视觉基线：左侧原图、二维码状态和字段框；右侧按模板字段定义生成的电子表格；底部为候选、规则、裁切、历史和导出影响。

真实队列包含：`待分类`、`识别中`、`待复核`、`规则异常`、`可导出`、`已导出需重导`。侧栏显示由 API 返回的真实计数和可点击筛选结果；不能保留无动作的导航按钮。

“保存草稿”保存当前人工编辑草稿与审核者身份，但不改变已确认事实；“确认并下一张”确认当前版本后从同一队列原子领取下一张可审核表单；“退回/作废”要求原因并写审计事件。审核锁的获取、续租、释放和管理员强制释放继续使用既有 Lease 机制。

## 7. 模板化导出闭环

导出中心按模板版本、日期范围、审核状态和导出状态筛选“可导出”记录。每个模板版本的 `export-map.json` 明确将 `field_key` 映射为 XLSX 业务列；导出程序不依赖 UI 字段名称。

导出前执行最终规则校验。通过后创建持久化 `XLSX_EXPORT` 任务，生成现有四工作表工作簿、保存不可变导出批次、文件哈希、包含的 `(form_id, record_version)` 和模板版本。导出完成后页面提供受控下载 URL、批次历史和反向追溯。已导出记录被更正后状态变为 `REEXPORT_REQUIRED`，旧导出文件不覆盖，新批次显式关联被替代批次。

## 8. 模块、API 与前端边界

| 模块 | 新增能力 |
|---|---|
| `templates` | 模板包、字段定义、坐标、版本、发布预检、QR/打印产物 |
| `forms` / `evidence` | 受控上传、模板绑定、原图和裁切关联 |
| `recognition` | QR 分类、定位校正、按模板识别、自动填充分流 |
| `rules` | 字段及跨字段预检、审核与导出前最终校验 |
| `review` | 草稿、真实队列、确认并领取下一张、退回/作废 |
| `reporting` | 模板映射导出、下载、批次与重导追溯 |

前端分为 `template-studio`、`import-center`、`review-workbench`、`export-center` Feature。Feature 只使用 API Client 和 Shell Ports；Web 使用 File/Camera Port，Tauri Desktop 以后以同一 Port 的实现替换，业务组件不得直接导入 Tauri API。

## 9. 分阶段交付

### Phase A：模板身份与导入骨架

- 新建模板及模板版本数据模型、发布状态和模板包校验。
- 设计器先支持“空白底稿图片 + 字段框 + QR + 四角定位标记”，导出 PNG 模板预览与 JSON 模板包。
- 增加受控图片上传 API、`FORM_IMPORT` 任务、QR 分类结果和“待分类”回退队列。

### Phase B：模板识别与审核分流

- 将模板字段坐标接入透视校正、裁切和既有 OCR/OMR。
- 实现字段阈值、自动预填来源、规则异常和真实审核队列。
- 完成草稿、退回/作废、确认并下一张和对应审计。

### Phase C：导出中心

- 实现模板导出映射、导出筛选、异步任务、下载 URL、导出批次与重导关系。
- 在导出前显示记录数、阻断错误和映射预览。

### Phase D：模板调优与桌面壳

- 支持复制已发布模板生成新版本、导入/导出模板包、版本差异比较。
- 为同一 React Feature 添加 Tauri v2 壳和 Desktop Port 实现。

## 10. 验收标准

- 新设计的纸质表单必含可读取二维码和四角定位标记；打印后拍摄样张可自动分到正确模板版本。
- QR 失败的图片不会猜测模板，进入待分类队列并记录人工选择。
- 同一张图片在不同拍摄角度下经校正后，字段裁切仍落在模板定义区域。
- 高置信度且规则通过的候选被自动预填；低置信度和错误字段必须在审核台可见并可更正。
- 每一条确认记录、图片、模板版本、规则结果和导出批次能双向追溯。
- 导出文件的每个业务列来自模板版本映射；更正后的已导出记录必须要求重新导出。
- 模板编辑、发布、导入、确认、退回/作废、导出均执行角色权限、幂等与审计要求。
