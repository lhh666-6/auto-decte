# 竹丝生产治理、检测闭环与权限整改设计

日期：2026-07-23
状态：已确认

## 1. 目标与范围

本次整改按四个可独立验收的阶段实施：生产数据安全、检测闭环、组织与工资权限、Android 安装与界面。核心业务约束必须由后端和数据库执行，前端只负责引导、展示和禁止明显无效操作。

## 2. 第一阶段：生产数据安全

### 2.1 笼号占用

- 占用范围为 `factory_id + cage_no`，不同工厂可使用相同笼号。
- 创建分选表时，在同一事务中创建笼号占用记录；存在有效占用时拒绝创建，返回可识别的业务冲突。
- 同一笼号不得在相同流程的未完成表中重复出现。
- 占用持续覆盖分选、浸胶、干燥和关联浸胶＋干燥表的主管审核。
- 关联浸胶＋干燥表通过主管审核后立即释放，不等待厂长签字或财务处理。
- 释放后允许进入下一轮分选，新流程使用新的记录编号，历史记录保持不变。
- 数据库唯一约束与事务冲突处理共同防止多台手机并发创建重复流程。

### 2.2 上游表单与可见范围

- 上游表以只读区块直接嵌入当前表单，不通过链接跳转。
- 一线员工只查看与当前工序直接相关的本厂表单。
- 检测员、主管、厂长可查看本厂未完成表单及完整上游链路。
- 财务和管理员可跨厂查看。
- 无修改权限时仍返回并显示完整只读数据，不出现空白页面。

## 3. 第二阶段：检测闭环

### 3.1 检测队列与唯一检测

- 表单进入检测队列时记录 `inspection_started_at`，检测截止时间固定为两小时后。
- 检测员无需先搜索即可看到本厂全部检测队列表单、表号和笼号；搜索只用于筛选。
- 第一位点击“开始检测”的检测员获得该表唯一检测资格。
- 一张表最多产生一份正式检测结果。
- 两小时从进入队列时计算，不因领取时间重置。

### 3.2 检测结果

- 合格时只需点击“检测合格”；系统自动记录检测员、时间、表号、笼号和结果，立即结束检测并开放厂长签字。
- 不合格时，文字、照片、录音至少提供一种。
- 页面提供独立的“填写问题”“拍照记录”“开始录音”操作。
- 不合格结果立即冻结厂长正常签字，由厂长选择具体工序退回整改。
- 被退回工序及受影响的下游签字、工资状态失效，旧版本和证据永久保留。

### 3.3 超时、提前签字与上诉

- 两小时到期后关闭正常检测入口并开放厂长签字。
- 厂长可在两小时内点击“提前结束检测并签字”，无需填写原因，但需要二次确认。
- 提前签字立即终止该表检测权限，并自动记录操作者、时间、剩余时长、表号、笼号和受影响检测员。
- 超时或提前签字后开放24小时上诉窗口。
- 若此前已有领取人，仅该检测员可上诉；若无人领取，本厂第一位领取上诉的检测员获得唯一资格。
- 每张表最多产生一份上诉检测结果。
- 上诉不自动推翻厂长签字。厂长同意后启动回溯整改；驳回必须填写原因。
- 检测员工作页分为“检测时间内”和“上诉期”。超过24小时从工作列表移除，但本人参与记录永久保留为只读历史。

### 3.4 通知

- 换岗成功、检测领取、提前终止、超时、上诉和审批结果均写入持久化消息中心。
- 用户授权且 Android/PWA 运行环境支持时，同步显示系统通知。
- 系统通知失败不得影响消息中心记录和业务事务。

## 4. 第三阶段：组织与工资权限

### 4.1 人员调动

- 普通员工不显示换岗申请按钮，后端也拒绝员工自行申请。
- 厂内调动采用“员工线下沟通—厂长提交—管理员批准并执行”。
- 跨厂调动必须依次取得原厂厂长和目标厂厂长同意，再由管理员批准并执行；管理员不能跳过双厂长同意。
- 任一厂长拒绝后申请关闭，并保存拒绝原因。
- 厂长的任免和调动仅由管理员执行。
- 调动成功后通知员工和相关厂长，保存原工厂、原岗位、目标工厂、目标岗位、生效时间及审批链。

### 4.2 厂长人员管理界面

- 人员管理使用独立路由和页面，不嵌在个人资料页或简易弹窗中。
- 手机端侧重查看人员、提交调动、处理跨厂审批和查看状态。
- 电脑端提供更宽的人员列表、筛选、详情和审批视图。
- 厂长仅管理本厂可分配岗位；管理员维护高权限岗位和全局组织关系。

### 4.3 工资权限

- 普通员工只能查看自己的工资。
- 厂长可查看本厂员工工资明细和汇总。
- 财务与管理员可查看所有工厂的工资明细和汇总。
- 查看、筛选、导出和审批均由后端按角色与工厂范围授权，并记录审计事件。

## 5. 第四阶段：Android 安装与界面

- 安装按钮优先使用浏览器提供的 PWA 安装事件，一次点击唤起 Android 系统安装确认。
- 浏览器和 Android 不允许网页静默创建桌面图标，系统确认不可绕过。
- 已安装时按钮显示“已添加到桌面”。
- 无安装事件时提供精简的浏览器菜单安装引导。
- 上游只读表使用当前页面内的可折叠区块，默认展示关键字段，可展开完整内容。
- 无权限页面统一显示只读内容或明确原因，不渲染不可访问的空白状态。

## 6. 数据一致性与错误处理

- 笼号占用、检测领取、上诉领取和调动审批均使用事务、唯一约束或乐观版本控制。
- 并发冲突返回 HTTP 409，并携带稳定业务错误码和当前占用信息。
- 权限错误返回 HTTP 403；不存在或已失效的记录返回 HTTP 404/410。
- 客户端刷新服务端状态后显示可恢复提示，不在本地伪造成功状态。
- 正式签字、审批、调动、检测提交和媒体上传必须联网；离线状态只允许保存未提交草稿。

## 7. 验收测试

- 同厂重复笼号、并发分选、主管审核释放、释放后复用和跨厂同笼号测试。
- 各角色本厂/跨厂可见性、只读上游嵌入和禁止修改测试。
- 两小时计时、唯一领取、合格快速完成、不合格证据、提前签字和签字冻结测试。
- 24小时上诉、唯一上诉资格、超时隐藏和只读历史测试。
- 厂内调动、跨厂双厂长审批、管理员最终执行和厂长任免测试。
- 员工、厂长、财务、管理员工资权限和审计测试。
- Android 安装状态、通知授权、响应式人员管理和无权限非空白测试。

## 8. 实施顺序

严格按第一至第四阶段推进。每阶段完成领域规则、迁移、API、前端和定向测试后独立验收，再进入下一阶段；不得先用纯前端隐藏代替后端约束。
