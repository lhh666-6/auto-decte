# 人工审核工作台：已确认的视觉与交互基线

状态：已确认，作为 React 审核工作台的实现基线。  
适用壳：Web Shell 与 Tauri Desktop Shell 共用。  
优先级：高于普通列表页和驾驶舱页面；先实现该页面。

## 1. 核心原则

审核员必须在同一屏同时看到“原始证据”和“可编辑数据”，而不是在图片、JSON、表格之间切换。点击右侧字段，左侧原图立即突出对应字段框；点击图片字段框，右侧表格定位并进入编辑态。异常优先处理，而不是要求逐项抄写。

推荐主布局为 **A：左图右表**。队列管理使用独立页面，驾驶舱使用独立页面，不要把三者塞入单个审核页面。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 深海蓝顶栏：产量采集工作台 / 人工审核 | 审核员、班组、系统状态              │
├───────────────┬─────────────────────────────────────────────────────────────┤
│ 队列侧栏      │ FORM 编号、模板版本、异常数、上一张/下一张                  │
│ 待分类      12│ ┌───────────────────────┬─────────────────────────────────┐ │
│ 待复核      28│ │ 原始表单证据           │ 电子表格（可编辑）              │ │
│ 规则异常     6│ │ 缩放/旋转/适配          │ 字段 / 识别值 / 置信度 / 确认值│ │
│ 可导出     104│ │ 字段框与当前字段高亮     │ 状态、错误原因、候选值          │ │
│               │ └───────────────────────┴─────────────────────────────────┘ │
│ 数据管理      │ ┌─────────────────────────────────────────────────────────┐ │
│ 模板与字段    │ │ 规则与建议 | 字段裁切 | 录音证据 | 历史版本 | 导出影响  │ │
│ 员工/工单     │ └─────────────────────────────────────────────────────────┘ │
│ 产品/工序     │ 作废/退回 | 保存草稿 | 确认并下一张                         │
└───────────────┴─────────────────────────────────────────────────────────────┘
```

## 2. 布局规格

| 区域 | 规格 | 目的 |
|---|---|---|
| 顶栏 | 48–56px，深海蓝 | 显示系统、审核员、班组、在线状态；不承载业务编辑。 |
| 左侧队列 | 桌面宽 190px，可折叠 | 待分类、待复核、规则异常、可导出计数；下面是模板、主数据、导出、驾驶舱导航。 |
| 表单上下文条 | 白底卡片 | Form ID、模板/版本、待确认数、上一张/下一张。 |
| 审核主区 | 左 47% / 右 53%，最小约 430px / 520px | 左侧证据优先可读，右侧保证字段编辑列不折叠。 |
| 证据画布 | 深色承载区，内部浅色纸张 | 原图缩放、旋转、适配；字段框和裁切框叠加在图上。 |
| 电子表格 | 舒适密度默认，每行 44–48px | 一次显示约 10–15 个标准字段；紧凑模式 32–36px 仅用于高吞吐审核。 |
| 底部抽屉 | 可折叠，默认展开异常 | 规则/建议、字段裁切、音频、版本、导出影响。 |

桌面小于 1280px 时保留左右结构但允许画布压缩；小于 960px 时切换为“图片 / 表格”两个可固定的面板，不允许把审核字段缩成不可读卡片。

## 3. 颜色、层级与状态

| 用途 | 色值 | 使用规则 |
|---|---|---|
| 顶栏、侧栏 | `#0F2742` / `#172F4D` | 工业控制台基调；文字用浅蓝白。 |
| 当前导航、焦点 | `#2563EB` | 仅表示选中、定位、当前编辑焦点。 |
| 正常/已验证 | `#16A34A` | 不用于大面积背景，只作状态标记、确认按钮。 |
| 待检查/警告 | `#F59E0B` + `#FEF3C7` | 低置信度、需确认、规则预警。 |
| 错误/阻断 | `#DC2626` + `#FEE2E2` | 数量闭合失败、必填缺失、冲突；当前图片框同步红色。 |
| 页面背景 | `#E9EEF5` | 不使用纯白大底，卡片才是白色。 |
| 卡片边框 | `#D7DEE8` | 保持低对比、清晰分区。 |
| 次级文字 | `#64748B` | 模板版本、页码、提示文字。 |

状态不能只靠颜色：每个状态必须同时有文字、图标或错误码。红色只表示需要处理的业务问题，不能作为普通强调色。

## 4. 电子表格规格

固定列顺序：`字段`、`识别结果`、`置信度`、`确认值`、`状态`。

- `确认值` 是唯一可直接编辑列；编辑前显示候选值与置信度；
- 当前字段整行有蓝色焦点边框，图片对应区域同步高亮；
- 阻断错误行使用浅红底、红色错误码和简短原因；
- 字段级规则错误直接展示，不把用户送到独立“错误页”；
- OCR/OMR 候选只能建议，不能自动覆盖人工确认值；
- “保存草稿”是中性按钮；“确认并下一张”是唯一主按钮；“作废/退回”必须是次级危险操作并要求原因。

## 5. 联动与交互验收条件

1. 选择表格行后，画布显示对应 source region、自动滚动到可见区域并高亮；
2. 点击画布字段框后，表格选中对应行、打开候选/裁切详情；
3. 修改确认值后，规则、异常数量、导出影响和按钮可用状态同步更新；
4. 审核租约状态始终可见；租约丢失、版本冲突或其他审核员占用时禁止静默覆盖；
5. 任务进度通过 SSE 显示在队列和当前表单上下文条中；
6. 历史版本、审计事件和录音只读，不能从 UI 覆盖原始证据；
7. AI 关闭时，AI 区域显示“未启用”，但人工确认流程不受影响。

## 6. 页面职责边界

- **审核工作台**：单张表单的图片—字段—规则联动，不放大盘统计。
- **队列页**：待分类、待复核、异常、任务状态、筛选和批处理。
- **驾驶舱**：统计卡片、趋势、分类维度、导出概览；选中记录后跳转审核工作台。
- **主数据/模板页**：员工、工单、产品、工序、模板和字段坐标版本管理。

React Feature 只能使用 API Client 与 Shell Port。Web/桌面差异只出现在 File、Camera、Scanner、Audio、Notification Port 的实现层，不能进入审核业务组件。
