## 1. 应用外壳与路由

一级导航固定为“审核工作台、模板中心、基础数据、导出数据”。顶栏同时显示产品名、服务上下文、当前位置和用户菜单占位，不包含登录功能。

| 路由 | 功能 |
|---|---|
| `/workbench/review` | 待核对审核工作台 |
| `/workbench/classification` | 待确认表单类型工作台 |
| `/workbench/recapture` | 待重新拍照工作台 |
| `/templates` | 模板库 |
| `/templates/:templateKey/versions/:version` | 精确只读模板版本 |
| `/templates/:templateKey/drafts/:draftId` | 模板草稿 |
| `/master-data/employees` | 员工 |
| `/master-data/work-orders` | 工单 |
| `/master-data/products` | 产品 |
| `/master-data/processes` | 工序 |
| `/exports` | 导出数据 |

`/` 重定向到 `/workbench/review`。刷新、浏览器前进/后退和复制链接均保持当前模块；未知地址显示应用内 404。存在未保存审核修改时，跨模块导航必须先确认。

## 2. 审核工作台

三类队列共用顶部表单上下文、左侧队列、中心工作区和底部动作：

- 待确认表单类型：二维码未绑定模板版本，要求人工选择精确已发布版本并填写原因。
- 待核对：显示图片证据和字段表格，执行正式审核。
- 待重新拍照：显示旧证据、退回原因和异常信息，并明确 replacement API 限制。

无表单时只显示与当前队列对应的空状态、上传照片和按编号查找，不保留无意义的大块空双栏。

### 2.1 加载、导入和审核锁

- “表单编号”与“加载表单”按编号打开已有表单。
- “导入图片”接受 PNG、JPEG 或 TIFF；成功后打开新表单。重复图片仍使用后端既有去重、测试恢复和清理语义。
- 所有审核写操作要求有效 Lease；没有锁时不能暂存、确认、更正、退回或作废。
- 切换表单或模块前如有未保存修改，必须明确确认；锁到期和并发冲突不得被静默忽略。

### 2.2 分类与识别进度

二维码失败时显示失败原因、精确已发布模板版本、模板摘要和分类原因。版本或原因缺失时不能提交，系统不得自动猜测相近模板。

分类成功后页面不跳走，而是每 500ms 查询识别任务：运行中显示“校正图片、裁切字段、生成识别结果”等中文步骤和百分比；成功后在原工作台加载字段表；失败、取消或中断时停止轮询，说明原因和重试方式。切换表单或卸载组件会取消旧轮询，旧响应不得覆盖新表单。

### 2.3 图片证据与字段联动

桌面宽屏为左图右表，可拖动分隔线，图片宽度限制在 35%–65%，选择保存于 `review-workbench-split-percent`。窄屏使用“图片/电子表格”标签，切换时保留选中字段和两侧滚动位置。

图片区支持：

- 原图/校正图切换；
- 25%–400% 缩放、滚轮缩放、拖动、每次 90° 旋转和复位；
- 字段框显示/隐藏；
- 点击字段框选择对应字段；
- 显示与选中字段关联的 `FIELD_CROP`，没有裁片时明确说明。

字段表显示识别值、最终值、置信度、候选、规则、主数据选项和错误原因。字段行与图片框双向联动，悬停不会改变正式选中项。加载表单时优先定位“填写错误 → 必填缺失 → 低可靠度 → 需要人工确认”的首个问题字段。

### 2.4 审核动作

- “暂存修改”只保存草稿，不创建正式记录版本。
- 首次审核使用“确认并审核下一张”，原子确认当前表单并领取下一张。
- 已有正式版本的表单使用“保存本次修改”，创建新记录版本；已导出记录进入需要重导状态。
- “退回重新拍照”和“标记为无效”使用应用内确认框并要求原因。
- 快捷键覆盖字段前后移动、暂存和确认；输入框、下拉框和弹窗内不会误触全局动作。

## 3. 模板中心

模板库顶部提供搜索、状态筛选、“导入模板包”和“创建模板”。模板包导入仍禁用并显示“暂未开放”，不伪造 API。

模板以中文名为主、编号为次；常用动作直接显示，退役和放弃草稿等危险动作放在“更多”并使用应用内确认框。已发布版本只读，任何调优都克隆新草稿。

预览页支持缩放、适合页面、适合宽度、复位、字段搜索、字段列表/画布双向联动，以及 PNG/PDF 产物入口。字段编号、文件名和哈希位于高级或追溯信息。

现有设计器仍只支持 A4/A5、比例坐标和自由字段；任意毫米尺寸、小模块和网格吸附不属于本轮能力。

## 4. 基础数据

员工、工单、产品、工序各有独立 URL，直接访问产品或工序不会回到员工。桌面布局为左侧记录列表、右侧当前记录详情；目录为空与搜索无结果使用不同空状态。

业务表单字段：

- 员工：工号、姓名、班组、岗位；
- 工单：工单号、工单名称、产品、数量、状态；
- 产品：产品编码、名称、规格型号、计量单位；
- 工序：工序编码、名称、工价、计量单位。

未知扩展属性保留在“更多信息”键值编辑器，不会因编辑已知字段而丢失。稳定编码不可修改；保存继续使用 `If-Match` 乐观版本。版本冲突显示“该记录已被其他人修改，请刷新后重试”，技术版本放在追溯详情。停用、恢复和变更原因继续保留审计语义。

## 5. 导出数据

导出按四步显示：

1. 选择数据；
2. 检查数据；
3. 生成 Excel；
4. 下载文件。

主按钮为“检查可导出的数据”。检查结果分为“将要导出的记录、无法导出的记录及原因、Excel 列对应关系”。只有存在有效预览和可包含记录时才显示生成动作；任何筛选变化都会立即使旧预览和创建资格失效。

任务运行时显示业务进度，成功后在当前页提供下载与历史记录。普通界面默认隐藏批次 ID、SHA-256、映射哈希、内部文件名和技术状态码；这些内容在“追溯详情”中完整保留。

排除原因按稳定原因码转换为中文业务说明，未知原因才回退后端消息。重导必须选择包含旧数据的来源批次，生成修正版并保留旧文件和 `supersedes_batch_id`；旧预览、旧刷新和卸载后的请求不得覆盖新状态。

## 6. 重新拍照边界

待重新拍照页面可展示旧证据、上次结果、退回原因和异常字段。“上传新的表单照片”复用现有导入流程，但当前只会创建新表单。

后端尚未提供把新照片永久关联为原表单 replacement evidence 的生产 API，因此界面不得声称已替换原照片或已保存追溯关系。完整后端要求见 [NEXT_TASK.md](NEXT_TASK.md)。

## 7. 必须保留的业务语义

1. 二维码失败不得自动猜模板，必须人工选择精确发布版本并填写原因。
2. 审核写操作必须有有效 Lease，并处理过期和并发版本冲突。
3. 未保存修改离开前必须提醒。
4. 候选值不能自动覆盖正式值；确认前必须通过规则和人工核对。
5. 退回、作废、模板退役、放弃草稿和主数据停用必须使用明确确认与原因语义。
6. 已发布模板不可原地编辑，只能克隆新草稿。
7. 导出前必须检查并展示排除原因；筛选变化使旧预览失效。
8. 导出后更正进入需要重导；重导创建新批次并保留旧文件。
9. 原图、校正图、字段裁片、记录版本、审计事件和导出批次必须可追溯。
10. 技术状态码、哈希和长 ID 默认隐藏，但在追溯详情可查。
11. replacement evidence API 不存在时必须如实标记阻塞。
